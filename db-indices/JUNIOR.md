# Индексы — Junior

## Зачем нужен индекс

Индекс — дополнительная структура доступа к данным. Позволяет находить подходящие строки без проверки всей таблицы, если запрос и тип индекса подходят друг другу. Аналогия: указатель книги помогает найти страницы, но не ускоряет чтение почти всей книги.

```sql
CREATE INDEX idx_users_email ON users(email);
SELECT id FROM users WHERE email = 'anna@example.test';
```

Индекс может помогать поиску по равенству/диапазону, JOIN и некоторым сортировкам. Он не меняет логический смысл запроса и не гарантирует порядок SELECT: для порядка нужен ORDER BY.

## Обычный и уникальный

Обычный индекс допускает повторяющиеся ключи. Уникальный дополнительно запрещает дубли согласно правилам СУБД:

```sql
CREATE UNIQUE INDEX idx_users_email_unique ON users(email);
```

Это альтернативный пример, не рекомендация создавать оба индекса на одну колонку. Правила NULL у UNIQUE зависят от СУБД; UNIQUE не заменяет NOT NULL. Уникальность должна обеспечиваться БД, а не только предварительным SELECT в приложении: между проверкой и записью возможна гонка.

## Цена и выбор оптимизатора

- Индекс занимает место на диске и в кэше.
- INSERT/DELETE требуют его поддержки; UPDATE индексируемых данных тоже добавляет работу.
- Построение и обслуживание расходуют ресурсы; лишние индексы могут ухудшить запись.

Оптимизатор выбирает план по оценке стоимости. Для маленькой таблицы или запроса большей части строк полный проход может быть дешевле индекса. Поэтому **наличие индекса не гарантирует использование и ускорение**. Индекс подбирают под реальные запросы, а пользу проверяют измерением/планом.

**Самопроверка:** что хранит индекс в дополнение к таблице? Чем уникальный отличается от обычного? Почему нельзя индексировать всё? Почему полный проход не всегда ошибка?
