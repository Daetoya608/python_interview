# Фронтенд

> Перевод страницы [Frontend](https://fastapi.tiangolo.com/tutorial/frontend/) документации FastAPI.
> Оригинал: © Sebastián Ramírez, лицензия MIT.

Статические фронтенд-приложения можно отдавать с помощью `app.frontend()` (или `router.frontend()`).

Это полезно для фронтенд-инструментов, которые генерируют статические файлы, например React с Vite, TanStack Router, Astro, Vue, Svelte, Angular, Solid и другие.

С такими инструментами обычно есть шаг сборки фронтенда командой вроде:

```bash
npm run build
```

Она сгенерирует директорию вроде `./dist/` с файлами фронтенда.

С помощью `app.frontend()` эту директорию можно отдавать, следуя соглашениям, которые нужны этим фронтенд-фреймворкам.

**FastAPI** сначала проверяет *операции пути*. Файлы фронтенда проверяются только в том случае, если не совпал ни один обычный маршрут, так что на ваш API это не повлияет.

## Отдача фронтенда

После сборки фронтенда, например командой `npm run build`, поместите сгенерированные файлы в директорию, например `dist`.

Структура проекта может выглядеть так:

```text
.
├── pyproject.toml
├── app
│   ├── __init__.py
│   └── main.py
└── dist
    ├── index.html
    └── assets
        └── app.js
```

Затем отдавайте её с помощью `app.frontend()`:

```python title="frontend/tutorial001_py310.py"
from fastapi import FastAPI

app = FastAPI()

app.frontend("/", directory="dist")
```

Так запрос к `/assets/app.js` может отдать `dist/assets/app.js`.

Если у вас также есть *операция пути* **FastAPI**, побеждает *операция пути*.

## Маршрутизация на стороне клиента

Многие фронтенд-приложения, включая **одностраничные приложения** (SPA), используют маршрутизацию на стороне клиента. Путь вроде `/dashboard/settings` может не быть реальным файлом, но фреймворк сам позаботится о его обработке.

Поэтому при прямом обращении к такому URL (а не при переходе внутри приложения) бэкенд должен отдать фронтенд-приложение из `index.html`, чтобы фронтенд-фреймворк затем обработал маршрутизацию на стороне клиента.

Для этого используйте `fallback="index.html"`:

```python title="frontend/tutorial002_py310.py"
from fastapi import FastAPI

app = FastAPI()

app.frontend("/", directory="dist", fallback="index.html")
```

**FastAPI** использует этот запасной вариант (fallback) только для запросов `GET` и `HEAD`, которые явно принимают HTML с `Accept: text/html` или `Accept: application/xhtml+xml`, как обычно делают запросы навигации браузера. Отсутствующие файлы вроде JavaScript, CSS и изображений по-прежнему возвращают `404`.

Запросы другими методами, например `POST` или `PUT`, к путям, которые совпадают только с запасным вариантом фронтенда, тоже возвращают `404`. Обычные *операции пути* **FastAPI** по-прежнему имеют более высокий приоритет, чем маршруты фронтенда.

> **Совет**
>
> По умолчанию `fallback` имеет значение `fallback="auto"`. В большинстве случаев указывать `fallback` не придётся. Подробности ниже.

Это то, что нужно для многих фронтенд-приложений с маршрутизацией на стороне клиента, например React с TanStack Router, Vue, Angular, SvelteKit или Solid.

## Собственная страница 404

Для отсутствующих путей фронтенда можно также отдавать статическую страницу `404.html`:

```python title="frontend/tutorial003_py310.py"
from fastapi import FastAPI

app = FastAPI()

app.frontend("/", directory="dist", fallback="404.html")
```

У такого ответа сохраняется код статуса `404`.

В этом случае **FastAPI** не будет отдавать `index.html` для отсутствующих путей фронтенда. Вместо этого он вернёт файл `404.html`.

> **Совет**
>
> По умолчанию `fallback` имеет значение `fallback="auto"`. При этом, если найден файл `404.html`, он будет автоматически использован как запасной вариант.
>
> Так что аргумент `fallback` обычно можно не указывать.

Это полезно с фронтенд-инструментами, которые генерируют статические HTML-файлы для каждой страницы, например Astro.

## Автоматический запасной вариант

По умолчанию `app.frontend()` использует `fallback="auto"`.

Если в директории фронтенда есть файл `404.html`, для отсутствующих путей фронтенда отдаётся этот файл с кодом статуса `404`.

Иначе, если есть файл `index.html`, для отсутствующих путей навигации браузера отдаётся `index.html` — этого и ожидают многие фронтенд-приложения с маршрутизацией на стороне клиента.

Поэтому в большинстве случаев можно использовать `app.frontend("/", directory="dist")` без указания аргумента `fallback`.

```python title="frontend/tutorial001_py310.py"
from fastapi import FastAPI

app = FastAPI()

app.frontend("/", directory="dist")
```

## Отключение запасного варианта

Если вы не хотите отдавать запасной файл для отсутствующих путей фронтенда, используйте `fallback=None`:

```python title="frontend/tutorial005_py310.py"
from fastapi import FastAPI

app = FastAPI()

app.frontend("/", directory="dist", fallback=None)
```

Тогда отсутствующие пути фронтенда вернут обычную `404`.

## Проверка директории

По умолчанию `app.frontend()` использует `check_dir="auto"`.

Когда переменная окружения `FASTAPI_ENV` равна `development`, **FastAPI** лишь показывает предупреждение, если директории с результатом сборки фронтенда нет. [Команда `fastapi dev`](https://github.com/fastapi/fastapi-cli#fastapi-dev) устанавливает эту переменную окружения за вас, если она ещё не задана. Это позволяет запускать бэкенд до сборки или запуска фронтенда во время разработки.

В любом другом окружении **FastAPI** возбуждает ошибку при создании приложения. Это помогает рано выявлять ошибки конфигурации, до развёртывания приложения без файлов фронтенда.

Можно также задать `check_dir=True`, чтобы всегда проверять директорию при создании приложения.

Если файлы фронтенда создаются позже, например отдельным шагом сборки после создания объекта приложения, задайте `check_dir=False`:

```python title="frontend/tutorial006_py310.py"
from fastapi import FastAPI

app = FastAPI()

app.frontend("/", directory="dist", check_dir=False)
```

С `check_dir=False` **FastAPI** не будет проверять директорию при создании приложения. Если настроенной директории всё ещё нет в момент обработки запроса, **FastAPI** возбудит ошибку тогда.

## Использование с `APIRouter`

Файлы фронтенда можно также добавить в `APIRouter` и подключить его с префиксом:

```python title="frontend/tutorial004_py310.py"
from fastapi import APIRouter, FastAPI

app = FastAPI()
router = APIRouter()

router.frontend("/", directory="dist", fallback="index.html")
app.include_router(router, prefix="/app")
```

В этом примере пути фронтенда отдаются под `/app`.

Любые обычные *операции пути* в приложении по-прежнему имеют приоритет, в том числе в других роутерах.

## Зависимости и middleware

Ответы фронтенда выполняются внутри обычного приложения **FastAPI**, поэтому к ним применяются HTTP-middleware.

Зависимости приложения, `APIRouter` и `include_router()` тоже применяются к ответам фронтенда. Это может быть полезно для защиты фронтенда аутентификацией через cookie или подобным способом.

Зависимости также могут изменять заголовки ответа и добавлять фоновые задачи — как и в обычных *операциях пути*.

## Только статический результат сборки

`app.frontend()` отдаёт файлы, уже сгенерированные сборкой фронтенда.

Он не выполняет рендеринг на стороне сервера (SSR). Он предназначен для фронтенд-фреймворков, генерирующих статические файлы, а не для фреймворков, которым нужен динамический рендеринг на сервере для каждого запроса.
