# CORS (Cross-Origin Resource Sharing)

> Перевод страницы [CORS (Cross-Origin Resource Sharing)](https://fastapi.tiangolo.com/tutorial/cors/) документации FastAPI.
> Оригинал: © Sebastián Ramírez, лицензия MIT.

[CORS, или «совместное использование ресурсов между разными источниками» (Cross-Origin Resource Sharing)](https://developer.mozilla.org/ru/docs/Web/HTTP/CORS), относится к ситуациям, когда фронтенд, работающий в браузере, содержит код на JavaScript, который взаимодействует с бэкендом, а бэкенд находится в другом «источнике» (origin), чем фронтенд.

## Источник (origin)

Источник — это сочетание протокола (`http`, `https`), домена (`myapp.com`, `localhost`, `localhost.tiangolo.com`) и порта (`80`, `443`, `8080`).

Так что всё это — разные источники:

* `http://localhost`
* `https://localhost`
* `http://localhost:8080`

Хотя все они на `localhost`, они используют разные протоколы или порты, поэтому это разные «источники».

## Шаги

Допустим, у вас есть фронтенд, работающий в браузере по адресу `http://localhost:8080`, и его JavaScript пытается взаимодействовать с бэкендом, работающим по адресу `http://localhost` (поскольку порт не указан, браузер предполагает порт по умолчанию `80`).

Тогда браузер отправит HTTP-запрос `OPTIONS` на бэкенд `:80`, и если бэкенд отправит соответствующие заголовки, разрешающие взаимодействие с этим другим источником (`http://localhost:8080`), то браузер на `:8080` позволит JavaScript во фронтенде отправить свой запрос на бэкенд `:80`.

Для этого у бэкенда `:80` должен быть список «разрешённых источников».

В данном случае список должен включать `http://localhost:8080`, чтобы фронтенд на `:8080` работал правильно.

## Подстановочные знаки

Можно также объявить список как `"*"` («подстановочный знак», wildcard), чтобы сказать, что разрешены все.

Но тогда будут разрешены только определённые виды взаимодействия — исключая всё, что связано с учётными данными: cookie, заголовки Authorization вроде используемых с Bearer-токенами и т. д.

Поэтому, чтобы всё работало правильно, лучше явно указывать разрешённые источники.

## Используйте `CORSMiddleware`

Это можно настроить в приложении **FastAPI** с помощью `CORSMiddleware`.

* Импортируйте `CORSMiddleware`.
* Создайте список разрешённых источников (в виде строк).
* Добавьте его как «middleware» в приложение **FastAPI**.

Можно также указать, разрешает ли бэкенд:

* Учётные данные (заголовки Authorization, cookie и т. д.).
* Конкретные HTTP-методы (`POST`, `PUT`) или все сразу с помощью подстановочного знака `"*"`.
* Конкретные HTTP-заголовки или все сразу с помощью подстановочного знака `"*"`.

```python title="cors/tutorial001_py310.py"
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()

origins = [
    "http://localhost.tiangolo.com",
    "https://localhost.tiangolo.com",
    "http://localhost",
    "http://localhost:8080",
]

app.add_middleware(
    CORSMiddleware,
    allow_origins=origins,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)


@app.get("/")
async def main():
    return {"message": "Hello World"}
```

Параметры по умолчанию в реализации `CORSMiddleware` ограничительные, поэтому нужно явно разрешить конкретные источники, методы или заголовки, чтобы браузерам было позволено использовать их в междоменном контексте.

Поддерживаются следующие аргументы:

* `allow_origins` — список источников, которым разрешено делать междоменные запросы. Например, `['https://example.org', 'https://www.example.org']`. Можно использовать `['*']`, чтобы разрешить любой источник.
* `allow_origin_regex` — строка с регулярным выражением для сопоставления с источниками, которым разрешено делать междоменные запросы. Например, `'https://.*\.example\.org'`.
* `allow_methods` — список HTTP-методов, разрешённых для междоменных запросов. По умолчанию `['GET']`. Можно использовать `['*']`, чтобы разрешить все стандартные методы.
* `allow_headers` — список заголовков HTTP-запроса, которые должны поддерживаться для междоменных запросов. По умолчанию `[]`. Можно использовать `['*']`, чтобы разрешить все заголовки. Заголовки `Accept`, `Accept-Language`, `Content-Language` и `Content-Type` всегда разрешены для [простых CORS-запросов](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS#simple_requests).
* `allow_credentials` — указывает, что для междоменных запросов должны поддерживаться cookie. По умолчанию `False`.

    Ни один из параметров `allow_origins`, `allow_methods` и `allow_headers` не может быть равен `['*']`, если `allow_credentials` равен `True`. Все они должны быть [указаны явно](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS#credentialed_requests_and_wildcards).

* `expose_headers` — указывает заголовки ответа, которые должны быть доступны браузеру. По умолчанию `[]`.
* `max_age` — задаёт максимальное время в секундах, в течение которого браузеры кэшируют CORS-ответы. По умолчанию `600`.

Middleware отвечает на два конкретных типа HTTP-запросов...

### Предварительные CORS-запросы (preflight)

Это любые запросы `OPTIONS` с заголовками `Origin` и `Access-Control-Request-Method`.

В этом случае middleware перехватит входящий запрос и ответит соответствующими CORS-заголовками, а также ответом `200` или `400` в информационных целях.

### Простые запросы

Любой запрос с заголовком `Origin`. В этом случае middleware пропустит запрос как обычно, но добавит в ответ соответствующие CORS-заголовки.
