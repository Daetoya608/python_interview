# Безопасность

> Перевод страницы [Security](https://fastapi.tiangolo.com/tutorial/security/) документации FastAPI.
> Оригинал: © Sebastián Ramírez, лицензия MIT.

Существует много способов обеспечить безопасность, аутентификацию и авторизацию.

И обычно это сложная и «трудная» тема.

Во многих фреймворках и системах одна только работа с безопасностью и аутентификацией требует больших усилий и большого количества кода (во многих случаях это может быть 50% и более от всего написанного кода).

**FastAPI** предоставляет несколько инструментов, которые помогают работать с **безопасностью** легко, быстро и стандартным способом, без необходимости изучать все спецификации безопасности.

Но сначала разберём несколько небольших понятий.

## Нет времени?

Если вас не интересуют все эти термины и вам просто нужно добавить безопасность с аутентификацией по имени пользователя и паролю *прямо сейчас*, переходите к следующим главам.

## OAuth2

OAuth2 — это спецификация, которая определяет несколько способов обработки аутентификации и авторизации.

Это довольно обширная спецификация, охватывающая несколько сложных сценариев использования.

Она включает способы аутентификации через «третью сторону».

Именно это используют «под капотом» все системы с «входом через Facebook, Google, X (Twitter), GitHub».

### OAuth 1

Существовал OAuth 1, который сильно отличается от OAuth2 и сложнее его, поскольку включал прямые указания о том, как шифровать передаваемые данные.

Сегодня он не очень популярен и мало используется.

OAuth2 не указывает, как шифровать передачу данных, — он ожидает, что ваше приложение будет работать через HTTPS.

> **Совет**
>
> В разделе о **развёртывании** вы увидите, как бесплатно настроить HTTPS с помощью Traefik и Let's Encrypt.

## OpenID Connect

OpenID Connect — ещё одна спецификация, основанная на **OAuth2**.

Она просто расширяет OAuth2, уточняя некоторые вещи, которые в OAuth2 относительно неоднозначны, чтобы попытаться сделать его более совместимым.

Например, вход через Google использует OpenID Connect (который «под капотом» использует OAuth2).

А вход через Facebook OpenID Connect не поддерживает. У него своя разновидность OAuth2.

### OpenID (не «OpenID Connect»)

Существовала также спецификация «OpenID». Она пыталась решить ту же задачу, что и **OpenID Connect**, но не была основана на OAuth2.

То есть это была полностью отдельная система.

Сегодня она не очень популярна и мало используется.

## OpenAPI

OpenAPI (ранее известная как Swagger) — открытая спецификация для построения API (сейчас она часть Linux Foundation).

**FastAPI** основан на **OpenAPI**.

Именно это делает возможными несколько интерфейсов автоматической интерактивной документации, генерацию кода и т. д.

В OpenAPI есть способ определять несколько «схем» безопасности.

Используя их, можно воспользоваться всеми этими инструментами на основе стандартов, включая системы интерактивной документации.

OpenAPI определяет следующие схемы безопасности:

* `apiKey`: ключ, специфичный для приложения, который может приходить из:
    * Параметра запроса.
    * Заголовка.
    * Cookie.
* `http`: стандартные системы HTTP-аутентификации, включая:
    * `bearer`: заголовок `Authorization` со значением `Bearer ` плюс токен. Это унаследовано от OAuth2.
    * HTTP Basic-аутентификацию.
    * HTTP Digest и т. д.
* `oauth2`: все способы OAuth2 для обеспечения безопасности (они называются «потоками», flows).
    * Некоторые из этих потоков подходят для создания провайдера аутентификации OAuth 2.0 (вроде Google, Facebook, X (Twitter), GitHub и т. д.):
        * `implicit`
        * `clientCredentials`
        * `authorizationCode`
    * Но есть один конкретный «поток», который отлично подходит для аутентификации непосредственно в том же приложении:
        * `password`: в нескольких следующих главах будут его примеры.
* `openIdConnect`: позволяет определить, как автоматически обнаруживать данные аутентификации OAuth2.
    * Именно это автоматическое обнаружение и определено в спецификации OpenID Connect.

> **Совет**
>
> Интегрировать других провайдеров аутентификации/авторизации, таких как Google, Facebook, X (Twitter), GitHub и т. д., тоже возможно и относительно легко.
>
> Самая сложная задача — создать подобного провайдера аутентификации/авторизации, но **FastAPI** даёт вам инструменты, чтобы сделать это легко, беря на себя основную тяжёлую работу.

## Утилиты **FastAPI**

FastAPI предоставляет в модуле `fastapi.security` несколько инструментов для каждой из этих схем безопасности, которые упрощают использование этих механизмов.

В следующих главах вы увидите, как добавить безопасность в свой API с помощью инструментов, предоставляемых **FastAPI**.

А также увидите, как это автоматически интегрируется в систему интерактивной документации.
