# FastAPI: конспект к аттестации

Объединяет темы учебника `lvl-1/01–51`: запросы, модели, ответы, зависимости, безопасность, БД, структура приложения, streaming и тестирование. Примеры используют Pydantic v2 и современный стиль `Annotated`. Возможности новых версий из исходника вынесены отдельно.

## 1. Что делает FastAPI

FastAPI — ASGI-фреймворк для HTTP API. Starlette предоставляет веб-механизмы, Pydantic — проверку и преобразование данных. Аннотации типов используются для валидации, сериализации и построения схем; сами аннотации Python вне такой библиотеки проверок во время исполнения не выполняют.

**OpenAPI** описывает API: маршруты, параметры, ответы и безопасность. **JSON Schema** описывает форму данных внутри этой схемы. По умолчанию `/openapi.json` содержит схему, `/docs` открывает Swagger UI, `/redoc` — ReDoc.

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/items/{item_id}")
async def read_item(item_id: int, q: str | None = None):
    return {"id": item_id, "q": q}
```

Установка: `pip install "fastapi[standard]"`. Для разработки: `fastapi dev main.py` или `uvicorn main:app --reload`; `main:app` означает объект app из модуля main. В варианте исходника с uv — `uv add "fastapi[standard]"` и `uv run fastapi dev`. Автоперезагрузка нужна при разработке; в исходнике для обычного запуска используется `fastapi run`.

Функция маршрута называется path operation function: декоратор задаёт HTTP-метод и путь.

- `async def` нужен для неблокирующего ожидания async-библиотек.
- Обычные `def`-маршруты и `def`-зависимости FastAPI выполняет в пуле потоков.
- Синхронная вспомогательная функция, которую вы сами вызвали внутри `async def`, автоматически в поток не переносится. Блокирующий I/O и тяжёлые вычисления там останавливают event loop.

## 2. Откуда берутся входные данные

| Объявление | Источник |
|---|---|
| Имя есть в шаблоне `/items/{item_id}` | Path-параметр |
| Обычный скалярный параметр вне пути | Query-параметр |
| Модель `BaseModel` без переопределения источника | JSON body |
| `Query()` / `Path()` / `Body()` | Явно заданный источник и ограничения |
| `Header()` / `Cookie()` | HTTP-заголовок / cookie |
| `Form()` / `File()` / `UploadFile` | Поля формы / загруженные файлы |
| `Depends(callable)` | Результат выполнения зависимости |

Path-параметры всегда обязательны. Для query и полей модели наличие значения по умолчанию делает их необязательными.

```python
from typing import Annotated
from fastapi import FastAPI, Path, Query

app = FastAPI()

@app.get("/items/{item_id}")
async def read_item(
    item_id: Annotated[int, Path(gt=0)],
    q: Annotated[str | None, Query(min_length=3, max_length=50)] = None,
    tags: Annotated[list[str] | None, Query()] = None,
):
    return {"id": item_id, "q": q, "tags": tags}
```

`?tags=python&tags=api` становится списком. Для списка query нужен явный Query, иначе сложный тип может трактоваться как body.

**Nullable и необязательность — разные вещи:**

- `name: str` — обязательно, None запрещён;
- `name: str | None` — обязательно, None разрешён как значение Python/JSON;
- `name: str | None = None` — можно не передавать.

У query нет встроенного JSON null: `?q=null` — строка `"null"`, `?q=` — пустая строка. Для bool распознаются, например, true/false, 1/0, on/off, yes/no; невалидное значение приводит к ошибке.

Маршруты проверяются по порядку: `/users/me` объявляют раньше `/users/{user_id}`. Ограниченные наборы значений задают Enum или Literal. Для захвата остатка пути со слешами используют `/files/{file_path:path}`.

## 3. Валидация и метаданные параметров

`Annotated[T, Query(...)]` сохраняет тип T и добавляет инструкции FastAPI. Значение по умолчанию указывают после `=`, не дублируют внутри Query в Annotated. Старый стиль `q: str = Query(...)` встречается в существующем коде.

| Ограничение | Значение |
|---|---|
| `gt`, `ge` | Больше; больше или равно |
| `lt`, `le` | Меньше; меньше или равно |
| `min_length`, `max_length` | Минимальная и максимальная длина |
| `pattern` | Регулярное выражение |
| `alias` | Внешнее имя, отличающееся от имени Python |

`title`, `description`, `examples`, `deprecated`, `include_in_schema` управляют описанием параметра. Примеры документируют запрос, но сами по себе не задают ограничений. Пользовательский `AfterValidator` Pydantic применяется после обычного преобразования типа; валидатор возвращает проверенное значение или возбуждает ошибку.

Невалидный вход по умолчанию даёт **422** с описанием расположения и причины ошибки. Валидация может преобразовывать допустимые представления, например строку query `"42"` в int; это не обязательно строгая проверка без преобразований.

## 4. Pydantic-модели и JSON body

```python
from typing import Annotated
from fastapi import Body, FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

class Item(BaseModel):
    name: str = Field(min_length=1, max_length=100)
    price: float = Field(gt=0)
    description: str | None = None
    tags: list[str] = Field(default_factory=list)

@app.post("/items/")
async def create_item(item: Item):
    return item

@app.put("/wrapped-item/")
async def replace_item(item: Annotated[Item, Body(embed=True)]):
    return item
```

Первый маршрут получает `{"name":"Book","price":10}`; второй — `{"item":{"name":"Book","price":10}}`.

- Несколько body-параметров получают собственные ключи в одном JSON-объекте: например, `item` и `user`.
- Чтобы скаляр считался частью body, используют `Body()`; иначе он обычно query-параметр.
- Вложенные модели, `list[Model]`, `set[str]`, `dict[str, float]` описывают вложенные данные. JSON-массив верхнего уровня можно принять как `list[Item]`.
- Set убирает дубликаты; в JSON-ответе передаётся массивом. Ключи JSON-объекта — строки, даже если модель преобразует их в другой допустимый тип.
- `HttpUrl`, `EmailStr` и другие специальные типы добавляют семантическую проверку.
- `model_dump()` даёт словарь, `model_dump(mode="json")` — JSON-совместимые значения, `model_dump_json()` — строку JSON. В старом Pydantic встречаются `.dict()` и `.json()`.
- `model_config = {"extra": "forbid"}` запрещает неизвестные поля; поведение по умолчанию обычно игнорирует extras.

Дополнительные типы: UUID передаётся строкой, datetime/date/time — строками ISO, set/frozenset — массивами. Сериализация timedelta, Decimal и bytes зависит от версии и конфигурации Pydantic и выбранного пути сериализации; не стоит переносить старые упрощённые правила на любой проект.

Примеры схем задают через `Field(examples=[...])`, `Body(examples=[...])` или `model_config["json_schema_extra"]`. `openapi_examples={...}` задаёт именованные примеры с `summary`, `description`, `value` для интерфейса OpenAPI.

## 5. Модели query, header и cookie

Связанную группу параметров можно описать моделью и указать источник: `Annotated[Filters, Query()]`, `Annotated[Headers, Header()]`, `Annotated[Cookies, Cookie()]`. Это переиспользует ограничения и валидаторы модели.

Внешние параметры остаются плоскими: поля query-модели приходят как `?limit=10&offset=0`, а не как JSON под ключом с именем модели.

Cookie читают через Cookie, заголовки — через Header: без явного указания обычный скаляр будет query. Header по умолчанию преобразует `_` в `-`: `user_agent` читает `User-Agent`; регистр заголовков не важен. Для другого имени есть alias. Повторяющийся заголовок можно принять списком. `convert_underscores=False` отключает замену, но заголовки с `_` могут не поддерживаться прокси.

В исходнике также описаны комбинирование нескольких моделей и необязательные группы параметров: без полей группа может быть None, при частичном заполнении проверяются все обязательные поля. Это зависит от версии FastAPI. `extra="forbid"` у одной такой модели может отклонять поля другой, потому что модель проверяет общий набор параметров своего источника.

## 6. Ответы и разделение моделей

Модель ответа задают аннотацией возвращаемого типа или `response_model=...`; явный response_model имеет приоритет. Она:

1. Проверяет возвращаемые данные.
2. Сериализует их и фильтрует поля по схеме.
3. Документирует ответ в OpenAPI.

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class UserIn(BaseModel):
    username: str
    password: str

class UserOut(BaseModel):
    username: str

@app.post("/users/", response_model=UserOut, status_code=201)
async def create_user(user: UserIn):
    return user
```

Здесь password не попадёт в ответ. В реальном приложении пароль проверяют и хешируют перед хранением. Модели входа, хранения и публичного ответа разделяют: например, UserCreate с password, UserInDB с password_hash и UserPublic без секретов. Наследование общей базы уменьшает дублирование.

Невалидный **ответ сервера** — ошибка приложения, обычно 500, а не клиентская 422.

- `response_model=list[Item]` — список объектов; union — один из нескольких форматов; типизированный dict — отображение.
- `response_model_exclude_unset=True` убирает поля, которые не были явно заданы, даже если у них есть defaults.
- `exclude_defaults` убирает значения, равные default; `exclude_none` — None. Это разные критерии.
- `response_model_include` / `exclude` фильтруют поля, но полная схема модели остаётся в OpenAPI. Для устойчивого публичного контракта лучше отдельная модель.
- `response_model=None` отключает построение модели ответа. При прямом возврате готового Response автоматическая проверка/фильтрация body моделью не выполняется.

В исходнике есть устаревшее утверждение, что `ModelA | ModelB` нельзя передать как значение response_model. Для современного Python это не универсальное ограничение; смысл union — допустимость одного из типов, а совместимость конкретной записи зависит от стека проекта.

## 7. Статусы и ошибки

| Статус | Смысл |
|---|---|
| 200 | Успех по умолчанию |
| 201 | Ресурс создан |
| 204 | Успех без тела ответа |
| 400 | Ошибочный запрос |
| 401 | Нет подходящих учётных данных |
| 403 | Недостаточно прав |
| 404 | Ресурс не найден |
| 409 | Конфликт состояния |
| 422 | Входные данные не прошли валидацию |
| 500 | Ошибка приложения |

`status_code=` в декораторе задаёт код ответа и отражается в документации; константы доступны в `fastapi.status`. У 204 и 304 не должно быть тела.

```python
from fastapi import HTTPException

def require_item(item):
    if item is None:
        raise HTTPException(status_code=404, detail="Item not found")
    return item
```

HTTPException **возбуждают**, а не возвращают. Обычное тело ошибки — `{"detail": ...}`. detail может быть JSON-совместимой структурой; `headers=` добавляет заголовки, например `WWW-Authenticate: Bearer`.

Глобальный обработчик: `@app.exception_handler(ExceptionType)`. Ошибки входа представлены `RequestValidationError`. Для перехвата и FastAPI-, и Starlette-HTTPException обработчик регистрируют на базовый класс Starlette. Стандартные обработчики можно переиспользовать из `fastapi.exception_handlers`.

## 8. Формы и файлы

`Form()` принимает поля формы: обычно `application/x-www-form-urlencoded`. Файлы с полями формы передают через `multipart/form-data`. Для разбора нужен пакет `python-multipart`.

В одном запросе можно комбинировать Form и File. Нельзя одновременно ожидать независимое JSON-body как `application/json`: тело запроса имеет один формат. JSON при необходимости передают строковым полем формы и разбирают явно.

| Объявление файла | Особенности |
|---|---|
| `Annotated[bytes, File()]` | Всё содержимое загружается в память |
| `UploadFile` | Буферизованный временный файл; удобнее для больших данных |
| `list[UploadFile]` | Несколько файлов под одним именем поля |

UploadFile предоставляет `filename`, `content_type`, `file`, а также `await read(size)`, `write(data)`, `seek(offset)`, `close()`. Повторное чтение требует `seek(0)`. В `def` можно пользоваться синхронным `upload.file`. Даже UploadFile не спасёт память, если вызвать read без ограничения и прочитать всё сразу.

Файл делают необязательным через `UploadFile | None = None`. Form-модель: `Annotated[FormModel, Form()]`. У неотмеченного HTML-чекбокса поле отсутствует, поэтому bool-полю обычно задают default False. В исходнике есть дополнительные версии комбинаций и дискриминируемых union форм — они требуют соответствующей версии FastAPI.

## 9. Кодирование, PUT и PATCH

`jsonable_encoder(obj)` преобразует модель и вложенные значения в JSON-совместимые структуры Python: например, datetime в строку. **Не возвращает строку JSON.** Полезен перед сохранением в хранилище, принимающее JSON-совместимые данные.

**PUT** обычно заменяет представление целиком: пропущенное поле может получить default и затереть прежнее значение. **PATCH** применяет только присланные изменения; это поведение нужно реализовать, имя HTTP-метода само ничего не сливает.

Алгоритм PATCH из учебника:

```python
update_data = incoming.model_dump(exclude_unset=True)
updated = stored.model_copy(update=update_data)
```

У входной PATCH-модели поля делают необязательными для передачи. Явно переданное None сохранится в update_data и может означать очистку поля; это отличается от отсутствующего поля. `model_copy(update=...)` не выполняет повторную полноценную валидацию итогового объекта: если нужны проверки объединённого состояния, провалидируйте его явно перед сохранением.

## 10. Depends и дерево зависимостей

Зависимость — вызываемый объект, который FastAPI выполняет и результат которого передаёт обработчику. Параметры самой зависимости могут читать запрос и включать другие Depends. Типичные задачи: текущий пользователь, доступ к БД, общая пагинация, проверка прав.

```python
from typing import Annotated
from fastapi import Depends, FastAPI, Query

app = FastAPI()

def pagination(limit: Annotated[int, Query(ge=1, le=100)] = 20):
    return {"limit": limit}

Pagination = Annotated[dict, Depends(pagination)]

@app.get("/items/")
async def list_items(page: Pagination):
    return page
```

- Передают `Depends(pagination)`, а не `Depends(pagination())`.
- Зависимость может быть def или async def независимо от вида обработчика.
- Класс тоже вызываемый объект: FastAPI анализирует его конструктор и передаёт созданный экземпляр. Сокращение: `Annotated[CommonParams, Depends()]`.
- Подзависимости образуют дерево. По умолчанию результат одной зависимости переиспользуется в рамках одного запроса. Это не глобальный кэш. `use_cache=False` отключает использование кэшированного результата для соответствующего объявления.
- Если результат не нужен, но проверка должна выполниться: `dependencies=[Depends(check)]` в декораторе.
- Общие проверки задают на `APIRouter`, при `include_router()` или через `FastAPI(dependencies=[...])`.
- Требования зависимостей включаются в OpenAPI; HTTPException прерывает обработку запроса.

## 11. Зависимости с yield и время жизни ресурсов

```python
def get_session():
    with Session(engine) as session:
        yield session
```

Это фрагмент для модуля, где уже определены Session и engine. Код до yield создаёт ресурс, значение yield внедряется, код выхода освобождает ресурс. Можно использовать try/finally. Зависимости освобождаются в обратном порядке с сохранением нужных им подзависимостей.

Перехваченное исключение нужно пробросить снова или заменить осмысленным исключением: случайное подавление скрывает ошибку от FastAPI. Ресурс должен жить столько, сколько его использует ответ, особенно при streaming.

В версии учебника:

- `Depends(..., scope="request")` — cleanup после отправки ответа; default для yield-зависимостей.
- `scope="function"` — cleanup после функции маршрута, до отправки ответа.
- Request-зависимость не может зависеть от function-зависимости с более коротким временем жизни. Function-зависимость может зависеть от обоих видов.

Поддержка scope и момент cleanup менялись между версиями FastAPI: это нужно соотносить с установленной версией. Фоновым задачам лучше открывать собственные ресурсы, передавая идентификаторы, а не сессию запроса.

### Lifespan приложения

Ресурсы на всё время работы **одного процесса приложения** создают/закрывают через lifespan; это другая область жизни, чем yield-зависимость запроса.

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI

@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.cache = {}
    try:
        yield
    finally:
        app.state.cache.clear()

app = FastAPI(lifespan=lifespan)
```

Каждый worker имеет собственный lifespan и память: словарь в app.state не становится общим кэшем всех процессов. Пул соединений/HTTP-клиент можно создать здесь, но Session для единицы работы — отдельно. При заданном lifespan старые обработчики `startup`/`shutdown` не вызываются автоматически вместе с ним. В тестах `with TestClient(app)` запускает вход/выход lifespan. [Lifespan FastAPI](https://fastapi.tiangolo.com/advanced/events/).

## 12. Безопасность: OAuth2, Bearer и JWT

**Аутентификация** определяет, кто пользователь. **Авторизация** — что ему разрешено. OAuth2 описывает делегирование доступа; OpenID Connect добавляет слой идентификации поверх OAuth2. Bearer означает, что предъявление токена даёт доступ; токен нужно защищать при передаче и хранении.

OpenAPI описывает схемы apiKey, HTTP Basic/Bearer, OAuth2 и OpenID Connect. Утилиты FastAPI упрощают извлечение данных и описание схемы, но не реализуют всю политику безопасности приложения.

Поток password из учебника:

1. Клиент отправляет username/password на `/token` как **поля формы**, не JSON.
2. Сервер получает пользователя и проверяет пароль по хешу.
3. Возвращает `{"access_token": "...", "token_type": "bearer"}`.
4. Клиент передаёт `Authorization: Bearer <token>`.
5. Зависимость проверяет токен, получает пользователя, проверяет его активность и права.

```python
from typing import Annotated
from fastapi import Depends
from fastapi.security import OAuth2PasswordBearer

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

async def get_current_user(token: Annotated[str, Depends(oauth2_scheme)]):
    # Здесь нужны проверка токена и получение пользователя.
    return await validate_and_load_user(token)
```

`validate_and_load_user` в этом фрагменте — функция вашего приложения. `OAuth2PasswordBearer` извлекает строку токена и описывает схему OpenAPI. Он **не проверяет подпись JWT**, не загружает пользователя и не создаёт `/token`. По умолчанию отсутствие подходящего Bearer-заголовка даёт 401.

`OAuth2PasswordRequestForm` разбирает username, password и дополнительные поля формы. `scope` приходит одной строкой с разделением пробелами, а `.scopes` даёт список. Названия scopes задаёт приложение; сами строки права не проверяют.

**Пароли:** хранят хеш с солью, а не исходное значение или обратимое шифрование. В учебнике используются pwdlib с Argon2 и проверка через verify. Фиктивное «хеширование» из начального примера не годится для реального хранения. Для отсутствующего пользователя выполняют проверку фиктивного хеша, уменьшая различие по времени ответа.

**JWT:** подписанные данные, обычно header.payload.signature. Подпись обнаруживает подмену, но **не шифрует payload**. В токен не кладут пароли и другие секреты.

- `sub` — строковый идентификатор субъекта, уникальный в нужном пространстве приложения.
- `exp` — срок действия; при создании используют время с часовым поясом UTC.
- При проверке задают доверенный ключ и явный допустимый алгоритм; недостаточно просто декодировать payload.
- Проверяют назначение токена: ожидаемые `iss` (issuer), `aud` (audience), сроки и обязательные claims согласно контракту. В PyJWT проверка `exp` при его наличии не означает, что токен **обязан** его содержать: обязательность задают, например, `options={"require": ["exp", "sub"]}`. Источник алгоритма/ключа должен быть доверенным, а не произвольным полем токена. [PyJWT decode](https://pyjwt.readthedocs.io/en/stable/api.html#jwt.decode).
- В учебнике используются PyJWT и HS256: один секрет для подписи и проверки. Секрет генерируют отдельно и хранят вне исходников.
- Истёкший или неверный токен — 401 с `WWW-Authenticate: Bearer`; наличие токена не отменяет проверки состояния пользователя и прав.

Password flow здесь нужен для понимания учебника, а не как рекомендация для нового OAuth2-входа. **Resource Owner Password Credentials grant запрещён актуальными OAuth2 Security BCP (RFC 9700 §2.4)**. Для пользовательского входа через провайдера применяют Authorization Code с PKCE и при необходимости OpenID Connect. Это ограничение конкретного OAuth2 grant, а не запрет любого собственного login endpoint. [OAuth2 Security BCP](https://www.rfc-editor.org/rfc/rfc9700.html#section-2.4).

## 13. Middleware и CORS

Middleware оборачивает обработку HTTP-запроса: код до `await call_next(request)` выполняется на входе, после — обрабатывает Response. Подходит для измерений, общих заголовков и логирования. Возврат Response из call_next не означает, что всё потоковое тело уже отправлено.

Последний добавленный middleware — внешний: на входе вызывается первым, на выходе последним.

**Origin** = протокол + хост + порт. Разные порты localhost — разные origins. CORS — браузерная политика доступа JavaScript к ответу API с другого origin; она не заменяет аутентификацию и не блокирует прямые запросы вне браузера.

`CORSMiddleware` настраивает:

- `allow_origins` / `allow_origin_regex` — разрешённые источники;
- `allow_methods` — методы;
- `allow_headers` — разрешённые заголовки запроса;
- `allow_credentials` — передачу credentials;
- `expose_headers` — нестандартные заголовки ответа, доступные JavaScript;
- `max_age` — срок кэширования preflight браузером.

Для запросов, требующих предварительной проверки, браузер отправляет OPTIONS preflight. Не каждый cross-origin запрос требует preflight. Для credentialed-сценариев используйте явные разрешения; wildcard `*` имеет ограничения и не является универсальной заменой настроек.

## 14. SQLModel и работа с БД

FastAPI не требует конкретной БД/ORM. В учебнике используется SQLModel поверх Pydantic и SQLAlchemy.

- `SQLModel, table=True` описывает таблицу; модель без table=True — данные API.
- `Field(primary_key=True)` задаёт первичный ключ; `index=True` — индекс.
- `id: int | None = None` позволяет создать Python-объект до генерации ID базой; это не обязательно означает nullable-столбец PK в БД.
- `engine` управляет взаимодействием с БД и соединениями; обычно его переиспользуют для одной конфигурации БД в процессе.
- `Session` отслеживает объекты и изменения. В учебнике отдельная сессия выдаётся на запрос через yield-зависимость.
- `SQLModel.metadata.create_all(engine)` создаёт отсутствующие таблицы, но не заменяет полноценные миграции изменённой схемы.

Базовые операции:

| Операция | Действия |
|---|---|
| Создать | `session.add(obj)`, `commit()`, `refresh(obj)` |
| Читать по PK | `session.get(Model, id)`, при отсутствии — 404 |
| Читать список | `session.exec(select(Model).offset(...).limit(...)).all()` |
| Обновить | Получить объект, применить `model_dump(exclude_unset=True)` через `sqlmodel_update()`, commit, refresh |
| Удалить | Получить объект, `session.delete(obj)`, commit |

`commit()` фиксирует транзакцию; `refresh()` перечитывает значения БД, например ID. Закрытие сессии не заменяет commit. При ошибке транзакции требуется корректный rollback/выход из контекста.

Разделяйте `HeroCreate`, `HeroUpdate`, `HeroPublic` и таблицу Hero: клиент не должен назначать серверный ID или получать секретные поля. Ограничивайте размер страницы.

SQLite `check_same_thread=False` снимает проверку использования соединения в разных потоках в конфигурации учебника; это не делает произвольное совместное использование Session безопасным. Синхронную Session не превращает в async сам факт вызова из async def.

## 15. Структура приложения и метаданные

Крупное приложение делят на пакет, например `app/main.py`, `app/dependencies.py`, `app/routers/users.py`, `app/routers/items.py`.

`APIRouter` группирует маршруты; `app.include_router(router, prefix="/items", tags=[...], dependencies=[...])` включает их в приложение и общую OpenAPI. Префикс обычно не оканчивается `/`, а пути операций начинаются с `/`. Роутеры можно вкладывать и включать с разными префиксами.

`app.mount(...)` подключает независимое ASGI-подприложение: его маршруты не объединяются автоматически с OpenAPI основного приложения. Это отличие от include_router.

У маршрута настраивают `summary`, `description` или docstring, `response_description`, `tags`, `deprecated`, `status_code`, дополнительные `responses`. Описание ответа в OpenAPI само по себе не реализует соответствующий ответ в коде.

У FastAPI задают title, summary, description, version своего API, contact, license_info, terms_of_service. `openapi_tags` описывает и упорядочивает группы. `docs_url`, `redoc_url`, `openapi_url` меняют адреса; None отключает соответствующий ресурс. Отключение OpenAPI отключает и использующие его встроенные страницы документации.

## 16. Streaming: JSON Lines и SSE

Streaming отправляет элементы по мере готовности без накопления всего ответа. Отличайте генератор в маршруте, который выдаёт данные клиенту, от yield-зависимости, которая управляет ресурсом.

**JSON Lines:** по одному JSON-значению на строку, без внешнего массива и запятых. В исходнике встроенная поддержка FastAPI отмечена с **0.134.0**: маршрут-генератор с yield, тип результата `AsyncIterable[Item]` или `Iterable[Item]`, media type `application/jsonl`. Тип элемента используется для проверки и сериализации.

**SSE:** односторонний поток событий сервер → клиент по HTTP, media type `text/event-stream`. События разделены пустой строкой; поля — data, event, id, retry; комментарии поддерживают соединение. Браузерный EventSource поддерживает получение событий и переподключение.

Встроенный `fastapi.sse.EventSourceResponse` в исходнике указан с **0.135.0**. Его задают как response_class и выдают элементы через yield. `ServerSentEvent(data=...)` JSON-кодирует данные; `raw_data=...` передаёт текст без такого кодирования. Оба поля одновременно не задают.

`id` позволяет клиенту сообщить `Last-Event-ID` при переподключении; сервер сам реализует продолжение с нужного места. `retry` задаёт интервал переподключения в миллисекундах. В реализации учебника предусмотрены keep-alive ping, Cache-Control и отключение буферизации некоторыми прокси.

SSE-ответ можно вернуть и на POST, но нативный браузерный EventSource делает GET; для POST нужен подходящий клиент. Обычный JSON, JSON Lines и SSE — разные форматы, клиент должен читать нужный протокол. Ошибка после начала отправки потока уже не может просто заменить отправленный статус обычной HTTP-ошибкой.

## 17. Фоновые задачи

FastAPI внедряет `BackgroundTasks` по типу параметра. `tasks.add_task(func, *args, **kwargs)` регистрирует работу после отправки ответа. Передают функцию, а не результат её вызова. Задача может быть def или async def; зависимости могут добавлять работу в тот же набор.

Это задачи внутри процесса приложения: нет гарантированного сохранения и повторного выполнения при падении. Подходят для небольшой необязательной работы; долгие и надёжно доставляемые задания требуют отдельной очереди и workers. Async-задача с блокирующим кодом всё равно может занять event loop. Ошибка фоновой работы не изменит уже отправленный ответ.

Передавайте фоновой задаче простые данные и идентификаторы; её Session/соединения должны иметь собственное время жизни.

## 18. Статика и фронтенд

`app.mount("/static", StaticFiles(directory="static"), name="static")` подключает отдачу файлов как отдельное приложение.

В версии исходника также есть `app.frontend("/", directory="dist")` и `router.frontend(...)` для готовой статической сборки. Обычные API-маршруты имеют приоритет; это не выполнение SSR.

- `fallback="index.html"` поддерживает клиентскую маршрутизацию SPA для подходящих GET/HEAD с HTML Accept.
- `fallback="404.html"` возвращает собственную страницу со статусом 404.
- `fallback="auto"` сначала выбирает 404.html, иначе index.html; `fallback=None` отключает запасной файл.
- Отсутствующие JS/CSS и другие ресурсы не должны превращаться в HTML-страницу.
- `check_dir` управляет проверкой каталога: auto допускает предупреждение в development и ошибку вне него; True всегда проверяет сразу, False откладывает проверку.
- Middleware и зависимости приложения/роутера применяются к frontend-ответам в описанном API.

Метод frontend и автоматическая обработка генераторов — возможности версии учебника; в старых проектах их может не быть. Их не следует путать с давно существующим StaticFiles.

## 19. Тестирование и отладка

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()

@app.get("/health")
async def health():
    return {"ok": True}

def test_health():
    with TestClient(app) as client:
        response = client.get("/health")
    assert response.status_code == 200
    assert response.json() == {"ok": True}
```

TestClient основан на HTTPX и вызывает приложение без отдельного сетевого сервера. Обычные тесты пишут через def и синхронные вызовы клиента, даже если маршрут async. Контекстный менеджер обеспечивает выполнение lifespan при тестировании.

`json=` отправляет JSON-совместимые данные, `data=` — форму, `files=` — файлы, `params=` — query, `headers=` — заголовки; cookie обычно задают на клиенте. Pydantic-модель сначала преобразуют в подходящую структуру, например jsonable_encoder.

Проверять стоит успешный запрос, ошибки типов/обязательных полей, отсутствие ресурса, неверную аутентификацию, отказ по правам, отсутствие секретов в ответе. Если тесту нужно напрямую await-ить async-код, используют асинхронный тестовый клиент и соответствующую среду тестирования.

Для отладки можно вызвать `uvicorn.run(app, host="0.0.0.0", port=8000)` под `if __name__ == "__main__":` и запустить файл через отладчик. Guard предотвращает запуск сервера при обычном импорте модуля.

## 20. Самопроверка

1. Почему аннотация int приводит к 422? FastAPI передаёт входные данные на парсинг/валидацию; при неудаче обработчик не вызывается.
2. `str | None` означает, что поле можно пропустить? Нет, для этого нужен default, например None.
3. Зачем response_model? Проверка, сериализация, фильтрация ответа и схема; особенно важно для исключения секретных полей.
4. Зачем Depends вместо обычного вызова? FastAPI разрешает параметры запроса, дерево зависимостей, кэш на запрос и cleanup ресурсов.
5. `OAuth2PasswordBearer` проверяет JWT? Нет, он извлекает Bearer-токен и описывает схему; проверку реализует другая зависимость.
6. JWT скрывает данные? Нет, подпись защищает от подмены, содержимое обычно читаемо.
7. Чем PATCH отличается от PUT? Частичное изменение против замены представления; при PATCH важно отделять отсутствующее поле от явно присланного None.
8. Почему sync-вызов внутри async def опасен? Он блокирует event loop; автоматический перенос применяется к def-обработчикам/зависимостям, а не любому вашему вызову.
9. Чем include_router отличается от mount? Первый объединяет маршруты с приложением и его OpenAPI, второй подключает самостоятельное приложение.
10. CORS обеспечивает защиту API от любого клиента? Нет, это браузерные правила доступа между origins; аутентификация и права проверяются отдельно.
11. BackgroundTasks переживут падение worker? Надёжного хранения и повторов у них нет.
12. Зачем отдельная Session на запрос? Чтобы изолировать состояние и жизненный цикл работы с БД; общий engine не означает общую Session.
