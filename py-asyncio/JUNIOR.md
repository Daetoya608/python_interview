# asyncio — Junior

## Модель выполнения

asyncio позволяет перекрывать ожидания I/O: пока одна задача ждёт сеть/таймер, тот же поток обслуживает другую готовую работу. Это **конкурентность**, а не одновременное выполнение Python-кода на нескольких ядрах.

**Event loop** исполняет готовые callbacks/продолжения задач, обслуживает таймеры и события I/O. Планирование кооперативное: исполняющаяся задача отдаёт управление при настоящей приостановке, а не через фиксированный квант времени.

| Объект | Смысл |
|---|---|
| Функция-корутина | async def без yield |
| Объект корутины | Конкретное приостанавливаемое выполнение; вызов функции ещё не запускает тело |
| Task | Управляет выполнением корутины в event loop, хранит результат/ошибку и принимает запрос отмены |

Ожидание часто связано с Future — объектом будущего результата. При завершении операции планируется пробуждение ожидающей Task. Корутина продолжает с сохранённого места; новый поток не создаётся.

## await и конкурентный запуск

`await child()` выполняет child в текущей Task; отдельная Task не появляется. Если child приостановится, приостановится вся цепочка. Если результат уже готов или child не приостанавливается, await может **не передать управление** циклу.

`await first(); await second()` запускает вызовы последовательно. Для перекрытия независимых ожиданий сначала создают задачи:

```python
import asyncio

async def load(value):
    await asyncio.sleep(0.01)  # Модель неблокирующего ожидания.
    return value * 2

async def main():
    first = asyncio.create_task(load(1))
    second = asyncio.create_task(load(2))
    assert (await first, await second) == (2, 4)

    assert await asyncio.gather(load(3), load(4)) == [6, 8]

    async with asyncio.TaskGroup() as group:
        task = group.create_task(load(5))
    assert task.result() == 10

asyncio.run(main())
```

Task обычно начинает исполняться, когда цикл получает управление. Ожидание уже созданных Task по очереди не делает их работу последовательной.

- **gather** собирает результаты в порядке аргументов и планирует переданные корутины. При первой ошибке по умолчанию пробрасывает её, но не отменяет соседей автоматически.
- **TaskGroup** (3.11+) владеет задачами блока, ждёт их, при ошибке одной отменяет остальные и дожидается завершения. Ошибки могут объединяться в ExceptionGroup. Это не откат уже выполненных действий.
- Отдельную фоновую Task нужно хранить, получать её ошибки и дожидаться завершения. Она не становится независимым процессом.

## Отмена и timeout

`task.cancel()` запрашивает отмену: при возобновлении корутины организуется CancelledError. Это не принудительное прерывание инструкции. После запроса **await-ят Task**, чтобы дождаться очистки. CancelledError — подкласс BaseException; `except Exception` его не ловит.

```python
import asyncio

async def main():
    started = asyncio.Event()
    cleaned = []

    async def worker():
        try:
            started.set()
            await asyncio.Event().wait()
        finally:
            cleaned.append(True)

    task = asyncio.create_task(worker())
    await started.wait()
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        pass
    assert cleaned == [True]

asyncio.run(main())
```

В самой рабочей корутине отмену обычно не подавляют: очищают ресурсы и пропускают исключение дальше. При отмене до первого запуска тело могло не войти в try/finally.

`async with asyncio.timeout(seconds):` ограничивает блок и на выходе превращает свою отмену в TimeoutError; ловят его снаружи блока. `await asyncio.wait_for(operation(), timeout=...)` ограничивает одну операцию, отменяет её по истечении и ждёт завершения отмены.

Это не жёсткий секундомер: занятый цикл обработает таймер позже, cleanup может продлить ожидание. Отмена локального запроса не откатывает действие удалённого сервера.

## Что блокирует цикл

`time.sleep`, синхронный HTTP/SQL-вызов и долгий расчёт внутри async def занимают поток event loop. Остальные задачи, таймеры и отмена в этом цикле не обслуживаются вовремя. Объявление async def не переносит обычные функции в потоки.

Используют async-библиотеку; блокирующий I/O можно вынести через `await asyncio.to_thread(function)`. Долгие Python-вычисления обычно выносят в процессы. Отмена ожидания потока не останавливает уже запущенную в нём функцию.
