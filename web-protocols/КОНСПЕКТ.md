# Веб-протоколы: быстро повторить

- HTTP: метод/target или статус, headers, необязательное тело. Текстовые строки — HTTP/1.1, HTTP/2/3 передают иначе. HTTPS защищает транспорт TLS.
- Safe — клиент не запрашивает изменение бизнес-состояния. Идемпотентность — одинаковый предполагаемый эффект одного и нескольких одинаковых запросов, а не одинаковый ответ. GET/HEAD/OPTIONS safe и идемпотентны; PUT/DELETE идемпотентны, но не safe. POST/PATCH не гарантируют идемпотентность; POST можно защитить прикладным idempotency key с сохранением результата.
- `Content-Type` — передаваемое представление; `Accept` — желаемое. `201` создано, `202` принято, `204` без тела, `304` использовать кэш, `409` конфликт, `429` превышен лимит.
- REST — ресурсы + ограничения стиля, не просто JSON CRUD. RPC — удалённые операции. SOAP — XML messaging framework. gRPC — контракт `.proto`, stubs, Protobuf, unary/streaming, deadlines.
- OSI снизу: Physical, Data Link, Network, Transport, Session, Presentation, Application. HTTP — application; IP — network; TCP/UDP — transport. HTTP/3 использует QUIC/UDP.
- Polling периодически спрашивает; long polling ждёт в запросе; SSE — поток server→client; WebSocket — двунаправленный канал. Восстановление бизнес-событий требует собственного протокола.
- `max-age` — свежесть, `no-cache` — хранить можно, использовать после валидации, `no-store` — не хранить. При **совпадении** ETag с If-None-Match условный GET/HEAD даёт 304 без тела; при изменении — новое представление. Несовпадение версии с If-Match при записи даёт 412, защищая от потерянного обновления.
- Persistent connections экономят установку соединения; HTTP/2 multiplexing не равен нескольким TCP-соединениям. TCP keepalive — отдельная вещь.
- Cookie: Secure — отправка через защищённый транспорт; HttpOnly — запрет чтения JavaScript; SameSite — ограничения cross-site отправки; scope/expiry — область и срок. Это не полная защита от XSS/CSRF. Cookie не гарантирует запрет кэширования; сессия может жить в БД/Redis.
- CORS регулирует браузерное чтение между origin. Preflight нужен не всегда. Для credentials нельзя ACAO `*`; CORS не авторизация и не CSRF-защита.
- Retry: безопасный повтор эффекта, ограниченный бюджет, backoff+jitter, учёт Retry-After. Timeout не доказывает, что сервер не выполнил операцию. Breaker: closed пропускает, open быстро отклоняет, half-open проверяет восстановление ограниченными пробами. Fallback должен быть допустим бизнесом; rate limiter ограничивает нагрузку.
- Асинхронная задача: 202 + URL статуса → worker → результат; outbox/ack/идемпотентность для сбоев. `async def` не заменяет надёжную очередь.
- Клик: URL/политики/кэш → DNS → соединение/TLS → HTTP/server → HTML/CSS/JS → rendering. Кэш и reuse могут пропустить этапы.
