# SQLAlchemy: краткий конспект для аттестации

Покрывает оба уровня требований. Подробные объяснения — `lvl-1.md` и `lvl-2.md`; запускаемые примеры — в `practice/`. Основной стиль — SQLAlchemy 2.0; Query остаётся legacy API.

## 1. Базовая модель

**ORM** связывает классы и объекты Python с таблицами и строками, строит SQL и отслеживает изменения. SQL и устройство БД всё равно нужно понимать.

```text
Engine → диалект, драйвер и пул соединений
Base.metadata → описание таблиц
ORM-класс → маппинг таблицы
Session → объекты, identity map, unit of work и транзакции
```

Engine и sessionmaker обычно общие на конфигурацию БД; Session создают на единицу работы. Одна Session не используется конкурентно несколькими потоками/задачами.

```python
from sqlalchemy import Integer, String, create_engine, select
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column

class Base(DeclarativeBase):
    pass

class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    name: Mapped[str] = mapped_column(String(80))

engine = create_engine("sqlite+pysqlite:///:memory:")
Base.metadata.create_all(engine)

with Session(engine) as session, session.begin():
    user = User(name="Anna")
    session.add(user)
    session.flush()
    user_id = user.id

with Session(engine) as session, session.begin():
    user = session.get(User, user_id)
    user.name = "Anna Updated"

with Session(engine) as session:
    print(session.scalars(select(User)).all())

with Session(engine) as session, session.begin():
    session.delete(session.get(User, user_id))

engine.dispose()
```

`Column(Integer, ...)` — другой допустимый способ объявления колонки; `mapped_column` сочетается с типизацией Mapped. `Mapped[str | None]` обычно означает nullable, `Mapped[str]` — NOT NULL. `String(n)` не является универсальной Python-валидацией длины.

## 2. Session и транзакции

| Действие | Смысл |
|---|---|
| `add(obj)` | Зарегистрировать объект для сохранения |
| `flush()` | Отправить изменения в БД внутри транзакции; часто получить ID |
| `commit()` | Flush + фиксация транзакции |
| `rollback()` | Откат и восстановление состояния Session после ошибки |
| `refresh(obj)` | SELECT для перечитывания объекта |
| `close()` | Освободить ресурсы; не commit |

- `with Session(...)` закрывает сессию. `with session.begin()` управляет commit/rollback.
- Autoflush может записать изменения перед SELECT. Commit выполняет flush даже при отключённом autoflush.
- После ошибки flush нужен rollback, прежде чем повторно использовать Session, либо её закрывают.
- Повторный get одного PK может вернуть тот же экземпляр из identity map; произвольные запросы от этого не становятся закэшированными.
- После commit атрибуты обычно expired. После close объект detached: догрузить неизвестные/истёкшие данные без Session нельзя.
- Не ставьте commit в каждой внутренней функции, если операция должна быть атомарной.
- `del obj` не удаляет строку: нужны session.delete и commit.

## 3. Связи

| Связь | Реализация |
|---|---|
| One-to-Many | FK у дочерней строки; у родителя коллекция relationship |
| Many-to-One | Тот же FK; у ребёнка скалярная relationship на родителя |
| One-to-One | Скалярные отношения + UNIQUE на FK; без UNIQUE это только ожидание ORM |
| Many-to-Many | Таблица связей с двумя FK; secondary в relationship |

`ForeignKey` обеспечивает ссылочную целостность БД. `relationship` даёт объектную навигацию; `back_populates` связывает две стороны. Для many-to-many пару FK обычно делают составным PK/UNIQUE, предотвращая дубли. Дополнительные поля связи — повод для association object.

`delete-orphan` удаляет принадлежащего родителю ребёнка, ставшего сиротой; подходит не любой связи. ORM cascade и ON DELETE CASCADE в БД — разные уровни. Удаление общей метки из task.tags должно удалять связь, а не саму метку.

## 4. Запросы

Следующие выражения используют полную учебную схему из practice/models.py:

```python
from sqlalchemy import func, select
from models import Task, User

stmt = select(User).where(User.age >= 18).order_by(User.id).limit(20)
join_stmt = select(User.name, Task.title).join(User.tasks)
count_stmt = (
    select(User.id, func.count(Task.id))
    .outerjoin(User.tasks)
    .group_by(User.id)
    .having(func.count(Task.id) >= 2)
)
```

WHERE — до группировки, HAVING — после. В LEFT JOIN count(дочерний PK) даёт 0 для родителя без детей; count(*) посчитает его строку. Несколько where-условий — AND; OR задают or_, а не Python or. Пагинация требует стабильной сортировки.

`session.execute` возвращает строки Row; `session.scalars` извлекает первую колонку — для select(User) это User. Для нескольких колонок не теряйте остальные через scalars.

`one()` требует ровно один результат; `one_or_none()` допускает ноль; несколько результатов вызывают ошибку. `session.scalar()` берёт первое значение без проверки единственности. `ScalarResult.first()` не добавляет SQL LIMIT: используйте select(...).limit(1).

Legacy-эквивалент: `session.query(User).filter(User.age >= 18).order_by(User.id).all()`. Query поддерживает join/group_by/having/subquery; для нового кода документация 2.x использует select. Query.get заменяют на session.get.

## 5. Загрузка связей и N+1

| Способ | Что происходит |
|---|---|
| Lazy select | SELECT при доступе к незагруженной связи |
| selectinload | Предварительная загрузка по IN ключей, при необходимости пачками |
| joinedload | Предварительная загрузка через JOIN; коллекции требуют unique() |
| subqueryload | Предварительная загрузка дополнительным запросом с подзапросом родителей |

**Eager — общая категория**, в которую входят selectin/joined/subquery. N+1 — выборка родителей плюс отдельные запросы связей в цикле. Для коллекций часто подходит selectinload.

`join` меняет выборку, `joinedload` загружает relationship; простой JOIN не гарантирует заполнение коллекции. При subqueryload + limit/offset нужен порядок по уникальному ключу. Сравнивайте SQL на свежих Session.

В **AsyncSession** обычное чтение незагруженной связи/expired-атрибута может попытаться выполнить неявный I/O и вызвать `MissingGreenlet`. Планируйте eager-загрузку, используйте явный `await session.refresh(obj, ["relation"])` или `AsyncAttrs.awaitable_attrs`. В async-коде часто задают `expire_on_commit=False`, чтобы commit не превращал следующий доступ к уже загруженному полю в неявный SELECT. Это не загружает отсутствующие связи и не гарантирует свежесть данных. [Async ORM и неявный I/O](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html#preventing-implicit-io-when-using-asyncsession).

## 6. Alembic

```text
Модели → metadata
БД + metadata → revision --autogenerate → проверенный файл миграции
Файл миграции → upgrade → обновлённая БД
```

1. `alembic init migrations` — создать окружение.
2. Настроить URL БД и `target_metadata = Base.metadata` в env.py; импортировать все модели.
3. `alembic revision --autogenerate -m "..."` — создать кандидат, вручную проверить.
4. `alembic upgrade head` — применить; `current` — версия БД; `history` — история.
5. `alembic downgrade -1` — выполнить обратные операции одной версии; `check` — проверить отсутствие новых предлагаемых изменений.

create_all не изменяет существующие таблицы под новую модель. Autogenerate не понимает все изменения и бизнес-преобразования; переименование может превратить в drop/add. Новые NOT NULL-поля требуют плана заполнения старых строк. Downgrade не восстанавливает уничтоженные данные автоматически. Для ряда ALTER в SQLite используют batch mode.

## 7. Вопросы с короткими ответами

1. **Flush уже сохранил данные?** SQL выполнен внутри транзакции, но без commit фиксации ещё нет.
2. **Почему SELECT вызвал IntegrityError?** Перед ним сработал autoflush накопленных изменений.
3. **Session — глобальный кэш?** Нет: она хранит identity map текущей работы, но не кэширует любые запросы.
4. **One-to-one обеспечивается relationship?** На уровне БД нужна уникальность FK.
5. **JOIN устраняет N+1 автоматически?** Нет, требуется соответствующая стратегия загрузки связи.
6. **Subquery и subqueryload — одно?** Нет: первое строит SQL-подзапрос, второе задаёт eager-загрузку relationship.
7. **Почему joinedload коллекции требует unique?** JOIN размножает строки родителя; результат явно дедуплицируют по идентичности объектов.
8. **Revision уже обновила БД?** Нет, она создала файл; изменения применяет upgrade.
9. **Можно делить AsyncSession между задачами?** Не для конкурентного использования: отдельная единица работы требует отдельной сессии.
