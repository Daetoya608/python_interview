# Типизация Python: конспект для аттестации

Оба уровня требований: базовые аннотации, None, mypy, коллекции, Union, Callable, TypeAlias и генераторы. Практика рассчитана на Python 3.11+; новый синтаксис type требует Python 3.12+.

## 1. Что дают аннотации

Python остаётся **динамически типизированным**: у объектов есть runtime-типы, имя может ссылаться на разные объекты. **Статический анализатор** проверяет совместимость операций и контрактов до запуска.

Аннотации сами не выполняют проверку или преобразование входа. Mypy не запускает программу. Они помогают найти ошибки типов, но не заменяют проверки бизнес-правил, тесты и валидацию внешних данных.

```python
name: str = "Anna"
age: int = 24
names: list[str] = []
ages: dict[str, int] = {"Anna": 24}

def greet(name: str) -> str:
    return f"Hello, {name}!"

def show(message: str) -> None:
    print(message)
```

`: T` описывает тип переменной/параметра, `-> T` — возвращаемого значения. Тип значения может выводиться из присваивания. Аннотация переменной без присваивания не создаёт готовое значение.

## 2. None и Optional

`Optional[T]` равнозначен `T | None`; второе написание доступно с 3.10.

```python
def display_name(name: str | None) -> str:
    if name is None:
        return "Anonymous"
    return name.upper()
```

Проверка исключила None — анализатор сузил тип до str. `if name:` также исключает пустую строку, что может не соответствовать требованиям.

| Сигнатура параметра | Можно опустить аргумент? | Можно передать None? |
|---|---|---|
| `name: str` | Нет | Нет |
| `name: str | None` | Нет | Да |
| `name: str | None = None` | Да | Да |
| `name: str = "Guest"` | Да | Нет |

Optional относится к допустимому **значению**, default — к допустимости **пропуска аргумента**. Таблица описывает контракт для анализатора: Python сам не отклонит None только из-за аннотации str.

## 3. Коллекции

| Аннотация | Смысл |
|---|---|
| `list[int]` | Список целых чисел |
| `dict[str, int]` | Строковые ключи, целочисленные значения |
| `set[str]` | Множество строк |
| `tuple[str, int]` | Ровно два элемента заданных типов |
| `tuple[int, ...]` | Произвольное число int |
| `dict[str, list[int]]` | Вложенные коллекции |

Старые List/Dict/Tuple из typing соответствуют привычным встроенным list/dict/tuple; встроенные параметризованные формы поддерживаются с 3.9.

Для входа функции удобно требовать минимально достаточный интерфейс из collections.abc: **Iterable[T]** для перебора, **Sequence[T]** для последовательности с индексами, **Mapping[K, V]** для чтения по ключам. Они не делают исходный объект неизменяемым.

List инвариантен: list[str] нельзя безопасно считать list[object], потому что через второй тип разрешалось бы добавить int. Read-only интерфейс часто позволяет безопасно принять более широкий круг коллекций.

## 4. Union

`int | str` / `Union[int, str]` означает одно из нескольких допустимых типов. Перед специфической операцией тип сужают через isinstance или проверку None.

```python
def normalize_id(value: int | str) -> str:
    if isinstance(value, int):
        return str(value)
    return value.strip()
```

`list[int | str]` может содержать смесь; `list[int] | list[str]` обещает один из двух однородных вариантов. Union не выполняет преобразований.

## 5. Callable и TypeAlias

```python
from collections.abc import Callable, Iterable
from typing import TypeAlias

Address: TypeAlias = tuple[str, int]

def apply(values: Iterable[int], fn: Callable[[int], str]) -> list[str]:
    return [fn(value) for value in values]
```

Callable[[int], str] — совместимый вызываемый объект, которому передают int и от которого получают str. Передают функцию **без вызова**. Callable[..., str] сохраняет только точный тип результата, ослабляя проверку параметров.

TypeAlias даёт имя существующему типу и не создаёт отдельный номинальный тип. Address и tuple[str, int] статически эквивалентны. Для различения идентификаторов разных сущностей одного alias недостаточно.

С Python 3.12 можно писать `type Address = tuple[str, int]`. На 3.11 это синтаксическая ошибка; future annotations новый синтаксис не добавляет.

## 6. Генераторы и async

**Generator[YieldType, SendType, ReturnType]**:

- YieldType — значение, выдаваемое потребителю.
- SendType — значение, отправляемое внутрь через send.
- ReturnType — итог return, доступный через StopIteration.value; обычный for его не выдаёт.

```python
from collections.abc import AsyncGenerator, Generator

def squares(limit: int) -> Generator[int, None, None]:
    for number in range(limit):
        yield number * number

async def stream_numbers(limit: int) -> AsyncGenerator[int, None]:
    for number in range(limit):
        yield number
```

Вместо полного интерфейса генератора можно вернуть Iterator[T]/Iterable[T], если потребителю нужны только элементы. Генератор — не list: список получают отдельной материализацией.

**AsyncGenerator[YieldType, SendType]** имеет два параметра. Итогового return со значением у async-генератора нет. Его читают через async for или await anext; значения отправляют через await asend. При необходимости явно закрывают через await aclose.

| Функция | Объект вызова | Получение результата |
|---|---|---|
| `def f() -> int` | int после исполнения функции | `f()` |
| def с yield | Генератор | for / next |
| `async def f() -> int` без yield | Корутина | `await f()` даёт int |
| async def с yield | Async-генератор | async for |

Для callback-корутины подходит `Callable[[int], Awaitable[str]]`. Обычную async def, которая после await возвращает str, аннотируют `-> str`, а не `-> Awaitable[str]`.

В примерах все параметры Generator и AsyncGenerator указаны явно: сокращения с defaults None доступны в новых версиях Python 3.13+, а практика работает на 3.11.

## 7. Mypy и ограничения проверки

Из `py-typing/practice`, после установки requirements.txt:

```console
python -m mypy
python demo.py
python -m mypy bad_examples.py
```

Первый запуск проверяет корректные typed_examples.py и demo.py в strict-режиме. Второй выполняет программу. Третий **должен найти ошибки** в отдельном учебном файле. Настройки находятся в pyproject.toml.

Частые ошибки: arg-type — неподходящий аргумент; assignment — присваивание; return-value — неверный результат; union-attr — операция не для всех вариантов; list-item — неверный элемент.

- Нетипизированные функции по умолчанию проверяются mypy ограниченно; аннотируйте границы. Check-untyped-defs не восстанавливает точный контракт из Any.
- Any разрешает почти произвольные операции без гарантии; object требует сужения перед специфической операцией.
- `typing.cast(T, value)` сообщает предположение анализатору, но не проверяет и не преобразует объект. `# type: ignore` подавляет диагностику, а не исправляет ошибку.
- `isinstance(x, list[int])` вызывает TypeError: параметризованный generic непригоден для этой runtime-проверки. `isinstance(x, list)` проверит лишь контейнер; типы элементов проверяют отдельно.
- Pyright — альтернативный анализатор с собственным выводом типов и настройками; практика проверена mypy.

## 8. Самопроверка

1. **Optional означает необязательный аргумент?** Нет: T или None. Пропуск задаёт default.
2. **Аннотация int преобразует строку?** Нет, для этого нужен явный int(...) и обработка ошибки.
3. **TypeAlias создаёт новый класс?** Нет, это псевдоним типа.
4. **Почему не list[object] вместо list[str]?** Изменяемость позволила бы нарушить исходный контракт.
5. **Что возвращает вызов генераторной функции?** Генератор, а не один yield-элемент и не готовый список.
6. **Какая разница между yield и return генератора?** Yield даёт очередной элемент, return завершает с итогом.
7. **Почему у AsyncGenerator нет ReturnType?** Async-генератор не поддерживает return со значением.
8. **Зелёный mypy гарантирует правильный алгоритм?** Нет, проверка типов не заменяет тесты и бизнес-валидацию.
