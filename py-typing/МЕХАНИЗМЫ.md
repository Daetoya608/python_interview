# Типизация: контракты и рассуждение о программе

Здесь объясняется, что именно знает анализатор и где заканчиваются его гарантии. Синтаксис — в [КОНСПЕКТ.md](КОНСПЕКТ.md), примеры для mypy — в [practice](practice/). Фрагменты ниже совместимы с Python 3.11+; новый оператор `type` требует 3.12+.

## 1. Runtime-объект и статический тип выражения

Python динамически типизирован: тип есть у объекта, а имя может перепривязываться к объектам разных типов. Аннотация описывает ожидаемый контракт для инструментов и читающего код человека; сама она не проверяет вход и не преобразует значение.

Статический анализатор читает программу и проверяет допустимость операций по известной информации. Он не обязан знать конкретное runtime-значение. Для выражения `name: str | None` он рассматривает оба варианта, пока код не исключит один из них.

```python
def twice(value: int) -> int:
    return value * 2

assert twice(3) == 6
# При запуске twice("a") вернул бы "aa"; анализатор отклонит такой вызов.
```

Одинаковые аннотации может использовать runtime-библиотека, например Pydantic. Но тогда проверку делает библиотека своим алгоритмом, а не интерпретатор автоматически из-за `: int`.

## 2. Тип как набор разрешённых операций

Тип полезно понимать как контракт: какие значения допустимы и какие операции над ними корректны. Для `Iterable[int]` обещан перебор int, но не индексирование или повторное чтение. Для `Sequence[int]` есть последовательный интерфейс с индексами. Для list дополнительно разрешено изменение.

На входе функции часто достаточно самого узкого по возможностям интерфейса, который она реально использует. Это расширяет набор подходящих реализаций. При этом аннотация Sequence не замораживает переданный list: кто-то ещё может его изменить.

Структурная типизация через Protocol описывает требуемые члены без обязательного наследования. Номинальная связывает совместимость с объявленными типами/наследованием. Оба способа выражают контракт, но выбирают разные основания для совместимости.

## 3. Union и сужение по потоку управления

Если значение имеет тип `A | B`, безопасная операция должна быть допустима для обоих вариантов либо предварительно исключить один. Анализатор следует веткам управления и уточняет тип.

```python
def display(value: str | None) -> str:
    if value is None:
        return "не задано"
    return value.upper()  # До этой строки доходит только str.

assert display("") == ""
```

Проверка `if value` смешала бы отсутствие и пустую строку. Сужение должно соответствовать предметному смыслу, а не только удовлетворять инструмент.

Optional[T] означает T или None, а не разрешение пропустить аргумент. Обязательность передачи задаёт default. Поэтому `x: str | None` — обязательный параметр с nullable-значением, `x: str = "guest"` — необязательный параметр без None в контракте.

Сужение не всегда сохраняется через произвольный вызов или изменение общего состояния. Если другой код может заменить поле, прежнее доказательство иногда уже неприменимо. Локальная проверенная копия часто делает и алгоритм, и типы понятнее.

## 4. Почему изменяемые коллекции инвариантны

Строка подходит там, где нужен object. Но из этого не следует, что list[str] подходит вместо list[object].

```python
def add_number(values: list[object]) -> None:
    values.append(42)

names: list[str] = ["Anna"]
# add_number(names)  # Анализатор отклонит: иначе в list[str] появился бы int.
```

Если интерфейс позволяет и читать T, и записывать T, свободная подстановка типов ломает одну из сторон. Поэтому list инвариантен. Read-only интерфейс Sequence ковариантен по элементу: чтение str допустимо как чтение object.

У вызываемых объектов направление параметров обратное: функция, умеющая принять любой object, справится со str. Функция, умеющая принять только str, не подходит для места, где её могут вызвать с произвольным object. Результат, напротив, можно уточнять. Это контравариантность входа и ковариантность выхода — следствие безопасной подстановки.

## 5. Generic сохраняет связь типов

Если функция «вернуть первый элемент» принимает Iterable[T] и возвращает T, общий параметр сохраняет информацию о типе элементов. Возврат object эту связь теряет, а Any отключает значительную часть проверки.

```python
from collections.abc import Iterable
from typing import TypeVar

T = TypeVar("T")

def first(values: Iterable[T]) -> T:
    return next(iter(values))

assert first([10, 20]) == 10
```

Пустой вход всё равно приведёт к StopIteration. Статическая совместимость типов не доказывает предусловие «есть хотя бы один элемент» и не проверяет правильность бизнес-результата.

`list[int | str]` описывает смешанную коллекцию. `list[int] | list[str]` обещает один из однородных вариантов. Выбор между ними определяет, какие операции вызывающая сторона может считать безопасными.

## 6. Any, object, cast и границы доверия

Object — обычный верхний тип: значение есть, но специфические операции требуют сужения. Any означает недостаток проверяемой информации и разрешает операции, которые могут оказаться ошибочными. Попадание Any из нетипизированной библиотеки способно распространиться по цепочке вызовов.

Cast сообщает анализатору предположение, а не делает runtime-проверку. Type ignore подавляет диагностику. Оба инструмента могут быть оправданы на границе с динамическим кодом, но не превращают неверные данные в правильные.

Внешний JSON сначала валидируют: тип контейнера, поля, значения и бизнес-ограничения. После этого внутренняя типизированная модель становится обоснованным контрактом. Простое `cast(User, payload)` такую границу не создаёт.

## 7. Имена типов и идентичность

Alias даёт удобное имя тому же типу. `UserId = int` как псевдоним не отличит идентификатор пользователя от идентификатора заказа. NewType позволяет статически различать такие значения, но не добавляет полноценной runtime-валидации и не создаёт обычный новый класс-обёртку.

Dataclass или другой класс-значение полезен, если нужны методы, проверка инвариантов и самостоятельная runtime-сущность. Выбор зависит от требуемой гарантии, а не длины записи аннотации.

## 8. Генератор имеет несколько направлений данных

Generator[Y, S, R] описывает три канала: yield выдаёт Y наружу; send принимает S внутрь; return завершает генератор итогом R. Обычный for читает выдаваемые элементы и не превращает итоговый return в очередной элемент.

Если потребителю нужен только next/for, часто достаточно Iterator[Y]. Полный Generator нужен, когда важны send, throw и возвращаемый итог. Ленивый итератор может быть одноразовым и удерживать ресурсы между шагами — аннотация элементов не описывает всю его жизнь.

У async def без yield аннотация `-> int` описывает результат **после await**. Сам вызов возвращает корутину. У async-генератора AsyncGenerator[Y, S] нет отдельного return со значением; его читает async for. Callable, возвращающий асинхронный результат, описывают через Awaitable[R].

## 9. Что означает зелёная проверка

Анализатор подтвердил согласованность известных ему контрактов в выбранной конфигурации. Он мог не проверить нетипизированные тела, получить Any из импортов или довериться cast/ignore. Тип int не ограничивает число положительными значениями, а тип списка сам по себе не обещает непустоту.

Полезная стратегия: типизировать границы модулей, ограничивать Any, читать причину диагностики, а затем проверять бизнес-сценарии тестами. Аннотации, тесты и runtime-валидация отвечают на разные вопросы.
