# Проектирование: быстро повторить

- Инкапсуляция защищает инварианты; абстракция задаёт контракт; полиморфизм допускает разные реализации. Наследование требует отношения подтипа, композиция часто уменьшает связанность.
- SOLID: **S** одна ось ответственности; **O** расширяем предусмотренное без изменения стабильного; **L** сохраняем контракт подтипа; **I** небольшие интерфейсы для конкретных клиентов; **D** детали зависят от абстракций политик.
- DI — способ передать зависимости, DIP — принцип их направления. Контейнер для DI необязателен.
- Singleton — один экземпляр в заданной области; Proxy — контроль доступа/ленивый доступ; Builder — шаги сборки; Factory — создание/выбор; Decorator — дополнительное поведение через обёртку.
- God object смешивает обязанности; magic numbers скрывают смысл. Процедурные и функциональные решения могут быть хорошими: ООП не обязательное лекарство.
- Низкая coupling между модулями, высокая cohesion внутри. DRY/DIE — не дублировать знание; KISS — понятное решение; YAGNI — не строить ненужное. BDUF полезен для рисков, опасен попыткой угадать всё.
- Layered разделяет обязанности по слоям. Clean направляет зависимости к бизнес-правилам. Hexagonal отделяет ядро портами от адаптеров.
- DDD: общий язык, bounded context, entity, value object, aggregate с инвариантами. Это не синоним микросервисов.
- Active Record сохраняет себя; Data Mapper отделяет сохранение от объектов. MVC разделяет ввод/модель/представление; MVVM вводит ViewModel и binding.
- Dynamic binding выбирает реализацию в runtime; это не аннотации типов. AOP выделяет сквозное поведение через middleware/декораторы и другие механизмы.
