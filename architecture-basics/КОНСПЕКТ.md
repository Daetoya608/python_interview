# Архитектура: быстро повторить

- Клиент инициирует запрос, сервер обрабатывает. Backend одновременно сервер для браузера и клиент для БД.
- Сеть может потерять ответ после успешного действия. Timeout не равен отмене; повтор побочного эффекта требует идемпотентности.
- Монолит — единый выпуск. Модульный монолит добавляет внутренние границы. Микросервисы дают независимость выпусков/масштабирования ценой сети и эксплуатации.
- Разделять по доменным границам и владению данными. Общая БД и обязательный совместный релиз могут превратить сервисы в распределённый монолит.
- Discovery находит живые адреса. Client-side balancing выбирает их у клиента; server-side — в промежуточном балансировщике.
- Синхронный вызов ждёт результат; асинхронный процесс получает его позже через очередь, статус задачи или callback. `async def` не определяет контракт системы.
- Stateless экземпляр не хранит обязательную локальную сессию между запросами; бизнес-данные всё равно существуют в БД. Stateful требует управления состоянием/восстановлением.
- Для устойчивости нужны timeouts/deadlines, ограниченные retries, backpressure, idempotency и наблюдаемость.
- Security: TLS, проверка прав на каждый объект, минимальные привилегии, безопасные секреты, валидация, аудит без чувствительных данных.
- Выбор архитектуры объяснять требованиями, измерениями и возможностями команды, а не модой.
