# CI/CD: быстро повторить

- CI — частая интеграция с автоматическими проверками. Delivery — готовность проверенного изменения к выпуску; deployment — автоматический выпуск.
- Pipeline состоит из jobs, jobs — из steps. Runner выполняет job; `needs` задаёт зависимости, matrix — варианты окружения.
- Быстрые проверки раньше дорогих. Ошибка проверки должна останавливать дальнейшие зависимые стадии.
- Artifact — проверенный результат сборки, cache — ускоритель. В production продвигают конкретную версию artifact.
- Воспроизводимость: фиксированные зависимости, явные версии среды, одинаковые команды локально и в CI.
- Минимальные права, secrets storage, осторожность с кодом PR из forks. Не публиковать секреты в логах.
- Release: environment/gates, миграции, health checks, ограничение конкурирующих выкладок, план отката/исправления.
- Уметь объяснить фактический pipeline своего проекта. Здесь активный CI не найден; [пример](practice/workflow.yml) учебный и не активирован.
