# CI/CD — уровень 1

**Continuous Integration (CI)** — частая интеграция небольших изменений с автоматической сборкой и проверками. Цель — быстро обнаруживать несовместимость и ошибки, пока изменение небольшое. Наличие Jenkins/GitHub Actions само по себе не означает CI, если ветки месяцами не интегрируют.

**Continuous Delivery** — каждое прошедшее проверки изменение подготовлено к выпуску; выпуск в production может требовать решения человека. **Continuous Deployment** — изменения, прошедшие заданные проверки, автоматически попадают в production. Поэтому сокращение CD нужно расшифровывать в контексте.

Типичный путь:

```text
commit/PR → lint/typecheck → unit tests → integration tests
          → build immutable artifact → staging/smoke → release → monitoring
```

- **Pipeline/workflow** — сценарий автоматизации, запускаемый событием или вручную.
- **Job** — набор шагов на runner/agent; независимые jobs могут идти параллельно.
- **Step** — команда или готовое действие в job.
- **Artifact** — результат, передаваемый между стадиями: пакет, образ, отчёт. Выпускают проверенный artifact с идентификатором версии/digest, а не незаметно пересобранный вариант.
- **Cache** ускоряет повторную работу, но не служит достоверным хранилищем результата релиза.
- **Environment** — целевое окружение с настройками, правами и возможными approval gates.

Проверки должны быть воспроизводимыми и завершать pipeline с ошибкой при провале. Быстрые проверки ставят раньше дорогих. Секреты берут из secret storage и не печатают. Для миграций и релизов заранее определяют совместимость, откат/исправление вперёд и проверку состояния после выкладки.

На собеседовании: CI отвечает за раннюю проверку интеграции; delivery — за готовность к выпуску; deployment — за автоматический выпуск. Зелёный pipeline снижает риск, но полнота гарантий зависит от качества проверок.
