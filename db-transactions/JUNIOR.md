# Транзакции — Junior

## Зачем нужна транзакция

Транзакция объединяет изменения в одну логическую операцию: либо фиксируется весь набор, либо изменения отменяются. Например, перевод денег не должен закончиться только списанием без зачисления.

```sql
BEGIN;
UPDATE accounts SET balance_cents = balance_cents - 100 WHERE id = 1;
UPDATE accounts SET balance_cents = balance_cents + 100 WHERE id = 2;
COMMIT;
```

Пример предполагает существующие счета и допустимое списание. В реальном коде проверяют количество изменённых строк и бизнес-ограничения; при проблеме выполняют ROLLBACK. Один BEGIN сам по себе не проверяет наличие денег или счёта.

| Команда | Действие |
|---|---|
| BEGIN | Начать явную транзакцию |
| COMMIT | Зафиксировать изменения |
| ROLLBACK | Отменить незакоммиченные изменения |
| SAVEPOINT name | Создать точку частичного отката |
| ROLLBACK TO SAVEPOINT name | Отменить изменения после точки, сохраняя транзакцию |
| RELEASE SAVEPOINT name | Удалить точку; не зафиксировать внешнюю транзакцию отдельно |

```sql
BEGIN;
UPDATE accounts SET balance_cents = balance_cents + 100 WHERE id = 1;
SAVEPOINT optional_step;
UPDATE accounts SET balance_cents = balance_cents + 50 WHERE id = 1;
ROLLBACK TO SAVEPOINT optional_step;
RELEASE SAVEPOINT optional_step;
COMMIT;
```

Если все операторы успешны, итог — увеличение на 100, не на 150. После COMMIT обычный ROLLBACK уже не отменяет результат: нужна новая исправляющая операция.

## ACID

- **Atomicity:** изменения транзакции фиксируются целиком или отменяются.
- **Consistency:** сохраняются заданные ограничения и инварианты. Их нужно выразить схемой/кодом: БД не знает бизнес-правила автоматически. Это не обещание одинаковых данных во всех репликах в любой момент.
- **Isolation:** конкурентные транзакции взаимодействуют по гарантиям выбранного уровня; наличие транзакции не означает отсутствия любых гонок.
- **Durability:** зафиксированный результат переживает сбой в рамках настроенных гарантий хранения. Это не замена резервной копии.

## Практические границы

**Autocommit** — режим, при котором отдельные операторы фиксируются без явно открытого многооператорного блока. Поведение зависит от драйвера: он может автоматически открывать транзакцию. Не предполагай, что после execute данные уже закоммичены; узнай настройки клиента.

В PostgreSQL ошибка оператора внутри транзакции обычно переводит её в **aborted state**: дальнейшие обычные команды не выполняются до ROLLBACK. Если заранее создан savepoint, можно восстановиться через ROLLBACK TO него. Простого перехвата Python-исключения недостаточно.

Не держат транзакцию открытой во время долгого HTTP-вызова или ожидания пользователя: удерживаются соединение, блокировки/версии, растут конкуренция и расходы обслуживания. Короткая транзакция охватывает нужную атомарную работу.

Внешнее письмо или платёж не откатывается вместе с БД. Закрытие соединения/Session не заменяет успешный COMMIT; незавершённую работу нужно явно завершать через корректный контекст или commit/rollback.
