# Транзакции — уровень 1

По [issue №6](https://github.com/Daetoya608/python_interview/issues/6): назначение, управляющие команды; дополнительно ACID.

## Назначение

Транзакция объединяет действия над БД в одну единицу работы. Например, перевод денег требует и списания, и зачисления: нельзя зафиксировать только половину операции.

```sql
BEGIN;
UPDATE accounts SET balance_cents = balance_cents - 1500 WHERE id = 1;
UPDATE accounts SET balance_cents = balance_cents + 1500 WHERE id = 2;
COMMIT;
```

Если операция не может быть завершена, выполняют ROLLBACK. В рабочем переводе дополнительно проверяют существование счетов, достаточность средств и конкурентные изменения: BEGIN не делает эти бизнес-проверки за разработчика.

| Команда | Смысл |
|---|---|
| BEGIN / START TRANSACTION | Начать транзакцию |
| COMMIT | Зафиксировать изменения |
| ROLLBACK | Отменить незавершённую транзакцию |
| SAVEPOINT name | Поставить точку частичного отката |
| ROLLBACK TO SAVEPOINT name | Откатить действия после точки, сохранив транзакцию |
| RELEASE SAVEPOINT name | Убрать точку; не является самостоятельным commit внешней транзакции |

```sql
BEGIN;
INSERT INTO accounts(id, balance_cents) VALUES (3, 1000);
SAVEPOINT optional_step;
UPDATE accounts SET balance_cents = 2000 WHERE id = 3;
ROLLBACK TO SAVEPOINT optional_step;
RELEASE SAVEPOINT optional_step;
COMMIT;
```

Счёт 3 сохранится с 1000, а не 2000. Savepoint не создаёт независимо фиксируемую вложенную бизнес-транзакцию.

## ACID

| Свойство | Что означает |
|---|---|
| Atomicity | Изменения транзакции фиксируются вместе либо отменяются |
| Consistency | Корректная операция переводит БД между состояниями, удовлетворяющими правилам |
| Isolation | Конкурентные операции видят друг друга согласно уровню изоляции |
| Durability | Подтверждённые зафиксированные изменения сохраняются в рамках гарантий системы |

Consistency не означает, что БД знает все бизнес-правила: их выражают ограничениями и кодом операции. Durability зависит от настроек журналирования/синхронизации и отказной модели; это не обещание пережить любой физический ущерб.

## Практические границы

- В autocommit каждый отдельный оператор может быть собственной транзакцией; несколько операторов не становятся атомарными автоматически.
- После COMMIT обычный ROLLBACK уже не отменит завершённую операцию: потребуется новое исправляющее изменение.
- Не держите транзакцию открытой во время ожидания пользователя или долгого внешнего HTTP-вызова: это продлевает жизнь блокировок/версий данных.
- В PostgreSQL ошибка обычно переводит транзакцию в aborted state до rollback или rollback to savepoint. Поведение других СУБД и отдельных ошибок может отличаться.
- Отправленное письмо или вызов чужого API не откатывается вместе с SQL.

Практика: `python db-transactions/practice/demo.py` проверяет полный rollback при нарушении ограничения и частичный откат к savepoint на SQLite.
