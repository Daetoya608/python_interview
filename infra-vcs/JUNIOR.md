# Git — Junior

## Модель

Git — распределённая система контроля версий: локальный репозиторий хранит историю, remote — другой репозиторий по настроенному адресу. GitHub/GitLab добавляют размещение, review и PR/MR, но не являются самим Git.

- **Working tree** — редактируемые файлы.
- **Index / staging area** — содержимое, подготовленное для следующего коммита.
- **Commit** — снимок дерева, родители и метаданные, не просто набор изменённых строк.
- **Ветка** — перемещаемая ссылка на коммит.
- **HEAD** обычно указывает на текущую ветку; возможен detached HEAD на отдельном коммите.
- `origin/main` — локальная remote-tracking ссылка, обновляемая fetch; не постоянно обновляемый вид сервера.

## Ежедневный цикл

```bash
git status
git switch -c feature/validation
# Изменить файлы.
git diff
git add path/to/file.py
git diff --cached
git commit -m "fix: validate order quantity"
git fetch origin
git merge origin/main
git push -u origin feature/validation
```

Add сохраняет в index текущую версию файла; более поздние правки нужно добавить снова. Diff показывает незастейдженные правки, diff --cached — подготовленные. Commit локален; push передаёт коммиты и предлагает обновить ссылки на remote.

**Fetch** получает объекты и remote-tracking ссылки, но не сливает их в текущую ветку. **Merge** объединяет истории: возможен fast-forward или merge commit. **Pull** получает изменения и интегрирует по выбранной стратегии/настройкам; не равен fetch. Для режима «только fast-forward» есть `git pull --ff-only`.

## Ветки, ignore, stash

```bash
git branch                # Список локальных веток.
git branch -a             # Также remote-tracking.
git switch main
git branch -m new-name     # Переименовать текущую ветку.
git branch -d old-name     # Удалить локальную, с проверкой слитости.
git stash push -u -m "unfinished work"
git stash list
git stash apply           # Применить, сохранить запись.
git stash pop             # Применить и удалить запись при успехе.
```

`.gitignore` исключает подходящие **неотслеживаемые** файлы из обычного добавления: например .venv/, __pycache__/, .env. Уже tracked-файл от этого не исчезнет из истории/отслеживания. Секрет нельзя безопасно «спрятать», просто добавив его в ignore после коммита.

Stash временно сохраняет незавершённую работу локально. По умолчанию tracked-изменения; `-u` добавляет untracked, но не ignored. Это не резервная копия.

## Конфликт и PR/MR

Конфликт означает, что Git не может автоматически объединить изменения. Посмотри git status, разберись с обеими версиями и маркерами `<<<<<<<`, `=======`, `>>>>>>>`, запиши нужный итог, проверь его, выполни git add и заверши merge через git commit. Отмена незавершённого merge — `git merge --abort`.

PR/MR — предложение объединить ветку на платформе. Обычно проходит review и проверки перед merge. Это не отдельный объект Git. Для аттестации нужно знать фактические правила своей команды: откуда ветвятся, кто проверяет, что блокирует merge. Они не определяются автоматически этими примерами.
