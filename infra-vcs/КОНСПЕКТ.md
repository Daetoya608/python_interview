# Git: быстро повторить

- Working tree → `add` → index → `commit` → локальная история → `push` → remote.
- Ветка — ссылка на коммит; `HEAD` обычно указывает на ветку. Commit хранит снимок, родителей и метаданные.
- `fetch` обновляет remote-tracking ссылки; `merge` интегрирует; `pull` получает и интегрирует по выбранной стратегии.
- `switch -c name`, `branch -m name`, `branch -d name`; `branch -a` — список. Удаление remote-ветки — отдельный `push --delete`.
- `.gitignore` не исключает уже tracked-файлы. `.gitconfig` — настройки; различайте local/global.
- `diff` — рабочее дерево против index, `diff --cached` — index против HEAD.
- PR/MR — review на платформе. Конфликт: понять обе правки → итоговый файл → add → commit/continue; abort отменяет незавершённую операцию.
- `stash -u` включает untracked, но не ignored; `apply` сохраняет запись, `pop` удаляет при успехе.
- `revert` добавляет обратный коммит; `reset` передвигает ветку. Soft сохраняет index/файлы, mixed — файлы, hard может уничтожить локальные изменения.
- `clean -nd` — preview, `-fd` — удаление untracked. `restore file` тоже отбрасывает правки.
- Amend/rebase меняют hashes. Cherry-pick переносит изменение коммита. Общую историю переписывают по договорённости.
- Worktree — параллельные каталоги одного репозитория. Reflog — локальный шанс восстановления, не backup.
- Gitflow — больше релизных веток; GitHub flow — PR в main; trunk-based — очень частая интеграция.
- Небольшие логические коммиты, понятные причины изменений, единая конвенция. Hooks ускоряют обратную связь, CI проверяет независимо.
- Реальный flow своей команды нужно знать отдельно: по этому репозиторию он не установлен.
