# Потоки — Junior

## Модель потоков и GIL

**Процесс** — отдельная область исполнения с обычно раздельной памятью. **Потоки** одного процесса разделяют память и ресурсы, но имеют собственные стеки выполнения; их планирует ОС. Общие данные удобны, но требуют синхронизации.

В обычной сборке CPython **GIL** допускает выполнение Python-байткода одним потоком за раз в одном интерпретаторе. Поэтому чистые CPU-bound вычисления обычно не ускоряются от добавления потоков. При ожидании I/O и в некоторых C-расширениях GIL освобождается: потоки могут перекрывать ожидания.

I/O-bound — узкое место в ожидании сети/диска; CPU-bound — в вычислениях. Для первого подходят потоки, для тяжёлого чистого Python-кода — процессы. Существуют отдельные free-threaded сборки; GIL не отключён во всех установках Python.

**GIL не заменяет Lock:** составное правило «прочитать → проверить → изменить» не становится одной атомарной операцией.

## Создание и ожидание

```python
from threading import Thread

def worker(number):
    print(number * 2)

threads = [Thread(target=worker, args=(i,)) for i in range(2)]
for thread in threads:
    thread.start()
for thread in threads:
    thread.join()
assert all(not thread.is_alive() for thread in threads)
```

- `target=worker` передаёт функцию; `target=worker()` вызовет её заранее.
- `start()` запускает работу в новом потоке, один раз для объекта Thread.
- Прямой `run()` не создаёт новый поток.
- `join()` ждёт завершения; возвращает None, а не результат функции.
- `join(timeout)` не останавливает поток. Затем `is_alive()` показывает, продолжает ли тот работу.
- Если делать join сразу после каждого start, задачи практически станут последовательными.

Ошибка worker не пробрасывается через join в родительский поток: завершает worker и обрабатывается threading.excepthook.

## Гонка и Lock

Гонка — результат зависит от порядка конкурентных действий. Два потока могут прочитать старое значение счётчика и записать одинаковое новое, потеряв увеличение.

```python
from threading import Lock, Thread

counter = 0
lock = Lock()

def increment():
    global counter
    for _ in range(1000):
        with lock:
            counter += 1

threads = [Thread(target=increment) for _ in range(2)]
for thread in threads:
    thread.start()
for thread in threads:
    thread.join()
assert counter == 2000
```

Все участники защищают одну логическую операцию **одним и тем же Lock**. Новый Lock внутри каждого вызова не защищает общие данные. `with lock:` освобождает блокировку и при исключении.

Критическую секцию держат короткой. Не вызывают join, удерживая блокировку, нужную завершающемуся потоку: получится взаимное ожидание. У Thread нет штатного безопасного принудительного kill; для остановки согласуют сигнал и дают worker выйти.
