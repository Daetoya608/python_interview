# Память Python — Junior

Механизмы ниже прежде всего о **CPython**. Язык Python не требует одинакового устройства памяти от всех реализаций.

## Зачем нужна сборка мусора

GC — автоматическое освобождение памяти объектов, которые программа больше не может использовать. В CPython два дополняющих механизма:

- **Reference counting:** объект удерживается сильными ссылками из переменных, контейнеров, атрибутов и внутренних структур. В обычном CPython исчезновение последней ссылки обычно запускает освобождение объекта.
- **Циклический сборщик:** ищет недостижимые группы, которые удерживают друг друга. Одного подсчёта ссылок для них недостаточно.

```python
a = []
b = a
del a             # Имя удалено, список жив через b.
b.append(b)       # Список теперь ссылается сам на себя.
del b             # Внешних ссылок нет, внутренняя остаётся: нужен cyclic GC.
```

Сборщик различает достижимость, а не бизнес-полезность. Если ненужные данные лежат в глобальном списке/кэше, они остаются достижимыми и GC их не удалит. Живой цикл не мусор, пока он доступен программе.

Упрощённо cyclic GC исследует отслеживаемые объекты, отделяет ссылки изнутри группы от внешних и находит недостижимую часть. Собираются не все объекты подряд: числа/строки не нуждаются в отслеживании циклов.

`gc.collect()` запрашивает сборку, но не уничтожает достижимые объекты. `gc.disable()` отключает автоматический cyclic GC, а не подсчёт ссылок. Освобождение объекта не гарантирует немедленного уменьшения памяти процесса: аллокатор может оставить её для повторного использования.

## del и __del__

`del name` удаляет привязку имени; `del items[i]` удаляет элемент. Это не прямой вызов финализатора и не команда уничтожить объект независимо от других ссылок.

`__del__` — финализатор при подготовке объекта к уничтожению. Время его вызова ненадёжно для управления ресурсами; при завершении интерпретатора вызов не гарантирован. Исключение из автоматического вызова не передаётся обычным образом в вызывающий код. Прямой `obj.__del__()` только вызывает метод.

Не полагайся на __del__ для закрытия файла/соединения: используй **with, close или try/finally**. Современный CPython умеет собирать обычные циклы с __del__; утверждение «такой цикл всегда утечка» устарело.

## Heap и stack

**Heap (куча)** хранит Python-объекты: списки, строки, числа, экземпляры. Локальность имени не переносит объект в системный стек.

**Стек вызовов** — цепочка активных вызовов с кадрами выполнения: локальные привязки, позиция исполнения, промежуточные значения. Размещение кадров — деталь реализации, их нельзя отождествлять с системным C-стеком.

```python
def make_list():
    items = [1, 2]
    return items

result = make_list()  # Вызов закончился, список жив благодаря result.
```

## __slots__: обзор

Slots задают места для фиксированных атрибутов и обычно убирают словарь экземпляра `__dict__`. Это может экономить память у большого количества однотипных объектов.

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x, self.y = x, y

point = Point(1, 2)
point.x = 3  # Поле можно менять: slots не означают immutable.
```

Необъявленное поле `point.color = "red"` вызовет AttributeError. Slots не проверяют типы, не устраняют память значений полей и не исправляют утечки ссылок. Если родитель имеет __dict__, slots потомка его не уберут; подкласс без slots обычно снова получает словарь.
